# Changelog

Versioning: the trm version lives in the `VERSION` file at the repo root
(shown as CFBundleShortVersionString). The **build number** is the git
commit count (`git rev-list --count HEAD`) — monotonically increasing and
unique per commit — stamped into the app together with the commit hash at
build time. Check yours with `trm version` or the About window. Build
numbers below mark the build at which each release's features shipped;
`≈` marks numbers reconstructed from commit dates for releases tagged
retroactively.

## 0.3.0 (Unreleased, builds 14407+)

### Added

- **Fixed: watermarks were lost when a group was restored.** A watermark lived only in the window TOML describing the pane that showed it — so a crash, which takes the TOML and leaves the sessions running, brought every pane back nameless and identifiable only by reading it. The session is the thing with an identity worth naming; the window is just where it was being shown. Watermarks are now remembered per session in `~/.trm/watermarks.json`, written whenever one changes and used as the fallback when no window TOML supplies one — so a session carries its name back into whatever window it lands in next.
- **The session browser opens a whole group as one window, even without a saved arrangement.** "Open Window" only appeared for groups that had a TOML describing their layout — and after a crash the group holding every pane is precisely the one that has no TOML, so the only way back was opening eleven sessions one at a time, each into its own window. Every non-empty group offers it now: with a saved arrangement it restores that, and without one it writes a grid — roughly square, never more columns than panes. A grid is not the layout that was lost, and it is enormously closer to it than eleven windows. The button says which you are getting (**Open Window** vs **Open All in One Window**), so it never quietly means something else.
- **Fixed: a remote pane's scrollback said to go and pair with the other machine instead of fetching it.** Every pane on a laptop that works through remote panes is one of these, so the phone could never read a terminal — it reported the refusal, which reads exactly like the feature being broken. The Mac fetches it over SSH now: the same round trip trm already spends asking that host whether a session is alive, for something far more useful. Trimmed on the far side so the padding a terminal writes to fill its width never crosses the network, and the whole path is async, since blocking the main actor for a second or two would freeze every window while a phone reads a terminal.
- **A button beside the reply box on the phone offers back what you've already sent.** Every prompt given to that agent, newest first; tapping one puts it in the box rather than firing it. A message worth repeating usually wants a word changed first, and a list where one wrong tap sends something to an agent is a list you use carefully instead of quickly. A button rather than a hidden gesture on the box: a double-tap there competes with placing the cursor and selecting a word, and nothing about it announces the history exists.
- **Tapping a card on the phone opens the agent in full: its terminal, with the reply box underneath it.** The board decides *which* agent needs you; dealing with the one you picked now happens on its own screen, beside the output you are judging — which is the right place for it, since the moment you doubt a summary the only useful thing is what actually scrolled past. The docked box on the board is gone. It was the wrong shape twice over: it spent a third of every card on a control that is empty almost always, and it made a card's tap ambiguous — a parent tap gesture over a navigation link, which is precisely what stopped the terminal opening at all. Drafts moved to the client so a half-written reply survives leaving the pane and coming back, and the card still shows it, because a draft you can't see is one you write twice.
- **The phone shows what it attached, takes a pasted image, and stops lying about its Return key.** A path in the reply box proves *something* was attached but not that it was the right picture, so thumbnails now sit above the box, each removable — removing one forgets the picture, not the path, since the file is on the Mac and the text is yours to edit. Pasting is offered whenever the pasteboard holds an image, because that is how a screenshot usually arrives: copied somewhere else and wanted here, without a trip through the photo library. And the keyboard's key is labelled **return** rather than **send** — on a field that grows vertically it inserts a newline instead of submitting, so the old label was the control misdescribing itself.
- **Fixed: tapping a card's watermark on the phone didn't open the scrollback.** The card carries an `onTapGesture` to aim the reply box, and as a *parent* gesture over a NavigationLink it won the race for the watermark's taps — so the one control that opens the terminal did nothing, and every tap anywhere aimed the box instead. It shares the gesture now, so the link fires and the box is still aimed. The affordance is a terminal glyph rather than a chevron, too: a chevron on a card that is already tappable reads as decoration, which is no help telling the one thing that navigates from the rest of the header.
- **Attach a photo to a message from the phone.** Pick one beside the reply box and it goes to the Mac, which writes it into `~/.trm/dropped-files` under the same stamped name the desktop uses — so two photos called `IMG_0001` can't collide — and answers with the path, which lands in your draft to write a sentence around. A path rather than bytes, because that is what an agent can actually open. Downscaled to 2000px on the long edge before sending: the wire is one JSON line, a modern phone photo is eight megabytes before base64, and nothing about reading a screenshot needs the full sensor. A row whose agent lives on *another* Mac is refused by name rather than handed a path to a file it could never open — pair with that machine instead.
- **The phone's scrollback view is readable now.** It opened at 10pt with two-axis scrolling, and terminal output is written for an 80-to-240-column window — the pane measured here had 240-character lines — so reading it meant panning a page-wide canvas with a thumb. It wraps by default at 12pt, with a wrap toggle for the cases where folding destroys the meaning (a table, a diff) and a size control that persists, because the size that suits your eyes doesn't change between sessions. The Mac trims before sending, too: terminal scrollback is padded to the pane's width, so most lines carried a tail of spaces that a wrapped line turns into half a screen of nothing, and an idle pane ends in a screenful of blanks that would land you below the last thing it said.
- **Fixed: an agent pane sometimes peeked without its overview, as though it had no agent.** The gate wanted positive evidence — a mirrored transcript on disk — and that evidence only exists *after* something has probed the pane. Peeking a pane for the first time is exactly the case where nothing has, so a real agent read as a plain shell. There are three answers now, not two: a probe found an agent, a probe found nothing, and **nobody has asked**. An unasked pane gets its overview opened, because opening it is what sends the probe — and if the answer comes back "no agent", the overview is taken away again. That is the only way to be right in both directions without making you wait on a round trip before the pane you asked for appears. Only an overview peek itself opened is ever retracted, and only while peek still holds it, so dismissing, peeking elsewhere or closing it by hand all take it out of scope.
- **Fixed: after a Reload Latest UI the Command Center came back on a different port, so every paired phone silently stopped working.** The reload overlaps the two processes on purpose, and the outgoing one still holds the port. Endpoint reuse used to carry that handoff, and quietly stopped when the listener became IPv4 — the outgoing process holds the port on an IPv6 dual-stack socket, and reuse won't share across families. The new process fell straight through to an ephemeral port (57810 on the machine this was found on) while the phone kept dialling 51735, with nothing on either end saying so. It now keeps asking for the remembered port once a second for six seconds before taking whatever is free: a few seconds unavailable is a smaller failure than a silent one that lasts until the next launch. Listener errors are logged in the clear too, rather than as `<private>` — this took an hour to find because the reason was redacted.
- **Fixed: `exit` in a remote pane left the pane open offering a Reconnect.** When a remote shell exits, trm asks the far machine whether the session really ended — closing on a dropped link would throw away running work, so it has to know which happened. It asked 250ms after the shell died. But zmx doesn't unlink its socket promptly: it sends SIGHUP, sleeps 500ms, sends SIGKILL, and only then deletes the socket file that the check looks for (`vendor/zmx/src/main.zig:1057`). Measured end to end, the socket survives **584ms** past `exit` — so the probe asked while it was still on disk, heard "still running", and kept the pane. It closed only when ssh happened to be slow enough to push the probe past the window, which is why it worked sometimes and looked arbitrary. The first probe now waits 700ms, clear of the daemon's own shutdown, with one retry behind it for a daemon that took longer — two round trips at worst, on an event that only happens when a shell exits.
- **Fixed: agents in projects with a dot or an underscore in the path never reached the board.** Claude Code flattens `/`, `.` *and* `_` to `-` when it names a project's transcript directory; trm folded only the slash. So `/Users/g/dev/flan_mcp` was looked up under `-Users-g-dev-flan_mcp`, which has never existed — the real one is `-Users-g-dev-flan-mcp` — the transcript wasn't found, and the pane was quietly reported as an ordinary shell rather than an agent. Two live agents were missing from a six-pane board for exactly this. Worktrees make it ordinary rather than rare: a worktree path contains `.worktrees`, and that `/.` folds to a double dash, so *every* agent working in one was invisible. Fixed in all four places the encoding was written out — the local locator, the prompt plugin, and both shell probes — now sharing one function with the rule spelled out.
- **A new worktree gets its own pane on the sidebar, whoever made it.** A worktree is a branch you can be in two places at once, which is the shape of most work here — one pane on `main`, another on what an agent is building. The moment the checkout exists it wants a pane. **New Worktree...** in the palette asks only for a branch name, derives the path beside the repo (`../<repo>-<branch>`, slashes flattened), creates the branch or checks out an existing one, and opens the pane. And trm watches the repositories its panes sit in, so a worktree an *agent* made with `git worktree add` gets the same treatment — that being the case that matters, since an agent has no way to tell trm what it just did. The pane is parked rather than dropped into the grid: a worktree is work you have started, not work you are looking at this second, and arriving as a new cell would shove aside the pane you were reading. Parking opens the shelf so it's on screen, and names the pane after the worktree's directory, because a shelf of panes all called "pane 7" is a shelf you open one by one. Worktrees that already exist get a pane too — the test is "has this one got a pane?", not "is this one new?", so opening trm in a repo with six worktrees gives you the five you aren't already sitting in. A worktree with a pane anywhere in it is left alone, which is what keeps the repository you're working in from acquiring a second pane, and the check is containment rather than equality since a pane deep in `repo/src` still attends `repo` — with a separator guard, because worktrees are named `repo-<branch>` and a plain prefix test would decide `repo-feat` was inside `repo` and never give it a pane at all. A pane you close stays closed. Scanning waits ten seconds after launch so restored panes can say where they are before it concludes a worktree has none. One `git worktree list` per distinct repo root every six seconds, only for repos a local pane is actually in.
- **Fixed: the phone could only reach a Mac on the same Wi-Fi.** The server bound an IPv6 wildcard socket and let Darwin deliver IPv4 to it as mapped addresses. That works on loopback and on ordinary interfaces, and does *not* work on the point-to-point `/32` utun Tailscale assigns — so the board answered from the same Wi-Fi and timed out from anywhere else, which reads like a Tailscale fault and isn't. (sshd looks healthy beside it only because launchd socket-activates it with a real IPv4 socket.) The listener is IPv4 now, with IPv6 added beside it best-effort, and every address the pairing code advertises is IPv4. Verified from the far side: loopback, LAN and tailnet all accept, where the tailnet used to hang.
- **A hosted session's row is named after its directory, not its hash.** A machine that hosts sessions without displaying them has no window TOMLs to take a watermark from — which is exactly the machine those rows come from — so every row read `trm-09661473`. It falls back to the working directory now: `dev/trm`, `dev/pe`, `src/moltis`.
- **The peek can be dragged wider or narrower, and double-clicked back to default.** A grip on each edge — either one drives the whole width, since the peek is centred and reaching for the nearer edge should always work. The pointer's travel is doubled into the width so the edge stays under the cursor instead of drifting away at half speed. Two widths are remembered rather than one, because the two peek layouts want different things and a single number would mean every switch between them undid the last adjustment: a terminal shown beside its overview wants the whole window to be worth reading, while a single pane at full width is just the grid with a scrim over it. Clamped to 30–100% of the window with a 320pt floor, since a peek too narrow to read has failed at its only job. Double-clicking a grip restores the default, which is the thing you want most after a drag that went too far.
- **Fixed: peeking a remote pane with no agent opened an empty overview.** The check took a remote pane at its word if trm had a session recorded for it — but *every* remote pane has one, including the ones that are just a shell, so any of them could spend a grid cell on an overview with nothing to show. It now wants positive evidence: a mirrored transcript on disk, which only exists once a probe actually found an agent on the far side. A missing mirror is no evidence rather than proof of absence, and erring toward not opening is the right way round — an overview you have to open yourself costs one click, while one you didn't ask for costs a cell and a rearranged layout. Local panes are unchanged; their process tree answers the question outright, for free.
- **Fixed: a board full of working agents all read IDLE.** "Working" was one signal — a tool call with no result yet — and that signal almost never fires. Claude Code writes the `tool_result` in the same breath as the `tool_use`, so a call only *looks* unfinished for as long as the tool actually runs, which for most calls is milliseconds. Measured against six live agents, two of them mid-turn with writes 3 and 7 seconds old: every one reported "all finished". An agent that is thinking or streaming text has no unfinished call at all, so it looked idle. A second signal now sits beside the first: a transcript that is *still being appended to* is an agent still working, for fifteen seconds after its last write. The two cover opposite halves — a ten-minute build keeps the unfinished call true while the file stays silent, and everything else keeps the write-recency true. Remote panes get it for free, since their local mirror's mtime advances as the stream lands. A clock skewed into the future doesn't count as live, so one badly-set machine can't pin every row to working.
- **One reply box on the phone, docked at the bottom, aimed by tapping a card.** There was a box on every card: a third of each card spent on a control that is empty almost always, cards pushed apart so fewer fit on a phone screen, and eight identical text fields on one screen when only one can ever be in use. Tapping a card now aims the single docked box at it, ringed in the card's own colour with the watermark beside the box so it never leaves you guessing which agent is listening. Tapping the same card again puts it away — the second tap on something you already chose reads as "never mind". The card scrolls to rest directly on top of the box, twice: once on the tap and again once the keyboard is up, since the keyboard resizes the safe area afterwards and a single scroll lands short by its height. A draft left behind when you tap a different card is kept and shown on its own card, because the docked box can only display the one it is aimed at and silently dropping the rest would be worse than not keeping them.
- **Tap a row on the phone to read the terminal behind it.** A briefing says what an agent concluded, which is the right thing to read almost always and useless exactly when the conclusion is the thing you doubt — then the only answer is what actually scrolled past. The watermark on a card now opens the session's scrollback, served over the same connection: the last 400 lines, monospaced, selectable, scrolled to the newest output rather than the top of a dump. Capped rather than sent whole, because a session that has run an agent all day holds a couple of hundred kilobytes and none of the part you want is at the beginning. Only sessions whose daemon runs on the Mac you asked can be read — a pane there that shells into another machine is a viewer, not the owner — and it says so by name rather than showing nothing, which is one more reason to pair with each machine rather than through one.
- **The idle dog moved into the reply box, in block glyphs.** It was line art taking sixty percent of the tile, which pushed out the sentence and the bullets — the things the row exists to show. It is three small rows now, drawn in solid blocks (`▟▀▀▀▙ ▌●▪●▐ ▜▄▄▄▛`) rather than slashes and underscores, because line art needs size to read and this has none to spare: it sits *behind* the reply box, at the trailing edge so it is never under the placeholder or the first words of a draft, faint enough that what you type wins. The one place on a card where "throw me the next one" is an instruction rather than an ornament.
- **The idle dog is the body of the row now, not a fidget in its header.** Six lines of ASCII taking sixty percent of the tile: floppy ears, a blink, a pant, and a frisbee nudged a little closer each loop. It takes the space the bullets and the sentence had, which costs nothing — an idle row's sentence is by definition the *previous* turn's, and it is one tap away in the pane. Every frame is the same number of rows and columns so nothing reflows mid-loop, and the type is sized from the height it is given rather than scaled down to fit, so it fills the space instead of floating in it.
- **Escape removes an overview that only existed to be looked at.** ⌘-clicking a Command Center card opens the agent's overview and peeks it; before, dismissing left the overview behind, so reading three agents off the board cost three grid cells and rearranged a layout you'd built. An overview opened by the click is now closed with the peek, exactly as one opened by peeking a pane is. One that was already open is someone's arrangement and outlives the peek untouched.
- **Peeking an agent's pane opens its Agent Overview beside it.** A terminal peeked on its own is half the pane: the terminal is the transcript scrolling past, the overview is what it came to — what you asked, what the agent said, what it wants from you. Peek already means "I want to work in this one now", which is exactly when both halves are wanted, and opening the overview by hand every time made one gesture take two steps. Only the overview's *existence* is arranged: the peek overlay already draws a terminal together with its bound overview in either direction, so the peek itself is unchanged. Gated on there actually being an agent — an overview of a plain shell shows nothing and still costs a grid cell. And it is undone on the way out: an overview that peek opened closes when the peek does, including when you peek straight from one pane to another without dismissing, because a transient gesture must not spend a grid cell permanently and rearrange a layout you built. An overview that was already open was someone's decision and is left alone.
- **Your phone pairs with every Mac you run agents on, and dials each one directly.** Pairing held exactly one machine, and the board it showed was a view of that machine's *panes* — so a mini running nine agents with no trm window open published an empty board, and the mini's agents were only visible through the laptop whose panes happened to be attached to them. Two changes make the phone independent of that. A machine now publishes the sessions it **hosts** as well as the panes it shows: a session with no pane anywhere still appears, marked `DETACHED`, and a reply goes straight to its zmx daemon (`zmx send`) rather than through a surface — the multi-client property `trm mirror` already relies on. And the phone keeps a pairing per machine, each on its own connection over its own tailnet address, merged into one board grouped by machine with each machine's connection state on its header. The mini's agents stay readable and answerable with the laptop shut, which is the point. Re-scanning a Mac's code replaces that Mac rather than adding it twice, so a rotated token is fixed by scanning again; the old single pairing migrates on first launch.
- **Every remote pane the Command Center drops now says why.** A remote pane whose probe finished without locating an agent transcript was removed from the board in silence — indistinguishable from a pane with no agent, and unanswerable when the board shows five rows for ten agents. Only the rarer no-session-recorded case said anything. Both are logged once per pane to `~/Library/Logs/trm/session.log` now, with the session name and the host.
- **Fixed: a briefing row cut its summary off at a numbered heading.** "Three things, all built and verified:" came out as "Three things, all built and verified: ## 1." — the extractor flattened the whole message to one line and then took everything up to the first full stop, and the stop it found belonged to a `## 1.` heading two lines down. It now walks the lines before joining them, because three of the four things that end a thought are only visible while they are still lines: a heading (complete on its own), a line ending in a colon (the lead-in to a list, which is exactly the sentence wanted and exactly the one that got swallowed), and a blank line. A colon *inside* a line still doesn't end it, so "Fixed: the retry loop was doubling its backoff." survives intact. A full stop after a bare number no longer counts as a sentence end at all — agents number their sections, and `1.` put a stop wherever a list was, far enough in to clear the old length check. Leading `#` and `>` are stripped, which the inline-markdown pass couldn't do because after joining there is no start-of-line left to recognise them by.
- **A phone that can't reach your Mac says which address and port it tried.** "Can't reach your Mac / Connection refused" is POSIX 61 with the useful half missing: a refusal is equally consistent with trm not running on the right machine and with the phone still dialling a port from a pairing two restarts ago, and those have opposite fixes. Every failure now carries its endpoint — the one that refused, and, when all of them are exhausted, the full list of what was dialled — set in a monospaced face you can actually compare digit by digit, and selectable so it can be pasted into a message.
- **An idle briefing row shows a dog that has brought the frisbee back.** The board says *needs you* / *check this* / *working* in colour, but "finished, and waiting on you" is the one state a colour says nothing about — it is the absence of one, and it is also the state most worth acting on. So idle rows get the only motion on the board: eleven monospace columns of a dog nudging a frisbee a little closer, panting, blinking, and waiting for the next throw. Deliberately not a spinner — nothing is in flight, and a progress shape would be claiming otherwise; what is wanted is the posture of expectancy. Every frame is exactly the same width so a row never reflows as it plays, all rows run off the wall clock so they fidget in step rather than as noise, and Reduce Motion gets the still frame.
- **Fixed: a link chip kept the markdown an agent wrapped it in.** `**https://claude.ai/…**` arrived as a link ending in two stars, which pastes somewhere that doesn't exist. Emphasis markers, backticks, angle brackets and quotes are stripped from both ends now — including the ones the link detector hands back percent-encoded, since a URL written inside backticks comes out ending in `%60` and no amount of trimming characters finds that. Briefing sentences lose their inline markdown too: a row that says `**Shipped** the fix` should read as prose, not as its own punctuation.
- **Copying from an Agent Overview says so where you tapped.** A copied link now flashes its own text for a moment — a confirmation at the other end of the pane is one you have to go looking for, and the eye is on the thing it just clicked. A code block's copy icon is drawn faintly at all times rather than only on hover (a button you can only find by hovering is one you don't know exists) and springs to a green checkmark when tapped.
- **⌥ and ⌘ text navigation works in the Command Center and Overview reply boxes.** Skip a word, jump to the start or end of the line, extend a selection while doing it, delete back to the start — all of it was going to the terminal, which answers key equivalents for the whole window. The relay hands those events to the field editor and lets AppKit map them, so ⌥⇧← and ⌘⌫ behave as they do in every other text field rather than as whatever a table in trm happened to list.
- **Session Browser tiles read their conversations without depending on the hook.** The remote probe was reading only the SessionStart hook's record, so a machine without the hook installed showed a wall of identical `claude --dangerously-skip-permissions` tiles — which was the whole complaint the summaries were meant to fix. Transcript resolution now lives in one place (`AgentProbeShell`), shared by the Session Browser and the Agent Overview's mirror: the hook's record when there is one, the process tree and file times when there isn't. Verified against a machine with nine live sessions — the seven running an agent resolve to their own transcripts, and the two whose agent has exited correctly resolve to nothing.
- **A Session Browser tile says whether it's attached.** In words — `Attached` / `Detached` — rather than a five-point dot with a tooltip, which is the kind of thing you only find when you already know it's there. Detached-and-unreferenced stays orange, since that is the state a lost pane ends up in.
- **Fixed: pairing kept going stale because Reload Latest UI stole the port.** The reload overlaps the old and new app deliberately, so the new one found 51735 still held, fell back to an ephemeral port, and *remembered* it — making one unlucky launch permanent and every paired phone wrong. The listener now allows local endpoint reuse so the handover keeps the port, and a fallback port is never remembered.
- **Fixed: walking back through reply history threw away the draft you were writing.** A TextField writes back through its binding when its contents change, including changes history itself made, so stepping looked like typing and cleared the very state that remembers the draft. It now knows its own echo, and Down all the way returns the half-written message you started with.
- **A narrow Agent Overview folds its header into one menu.** Eleven controls — sections, typeface, three text-size buttons, speak, bionic, refresh, close — cannot fit across a column in a six-pane grid, and squeezing them is what pushed the header past the pane's own width and over its neighbour. Under 380pt the header keeps only what you reach for mid-read (the turn arrows, close) and everything else moves into a hamburger menu, grouped Show / Type. The title truncates before anything else gives way, since a clipped title costs nothing and a header that won't fit costs the pane beside it.
- **Fixed: pairing broke on every trm restart with "connection refused".** The Command Center server took a fresh ephemeral port each launch, so a scanned code was stale as soon as trm was relaunched — the phone kept dialling the old number. It now asks for a fixed port (51735) and remembers whichever it ends up with, falling back to a free one if that is taken. A refused connection is at least an honest message; this is why it was appearing.
- **Fixed: a narrow Agent Overview painted over the pane beside it.** Stopping the context pill from wrapping had made the header refuse to shrink, so a narrow cell pushed the whole overview wider than its own bounds. The pill now degrades in steps — full `83% ctx`, then a coloured dot when there's no room for words, then nothing — and the overview clips to its cell, so no future stray intrinsic width can reach a neighbour.
- **Session Browser tiles show the conversation, not the command.** Every agent pane runs the same thing, so a browser full of `claude --dangerously-skip-permissions` was the same tile twelve times over and no help finding the session you meant. A tile now leads with the last thing you asked and a sentence of what the agent said back, with the agent's name and the pane's watermark beneath — the command only stands in for a session that is just a shell. Local sessions resolve through the same locator the Agent Overview uses, so a tile and an overview never disagree about which conversation a pane is having. Remote sessions get theirs in **one** extra round trip per machine: the probe reports where each agent's transcript lives (from the SessionStart hook's record) and a single follow-up fetches the tail of each, fenced by session name, rather than one connection per session.
- **Fixed: a phone refused by the Command Center saw a dropped socket instead of the reason.** The server sent `bad token` and cancelled the connection in the same breath, so the bytes never left — the refusal now waits until it is actually on the wire. Found while testing the protocol by hand rather than from the app.
- **`scripts/deploy-to-mac.sh`**: installs a local build onto another Mac and then signs it there with a real identity, because an ad-hoc signature changes every build and macOS ties privacy grants to the signature. The one that matters is Local Network: without it the Command Center server listens, accepts nothing from other devices, and the phone times out with no error to show anyone. Signing needs the login keychain, which an SSH session can't unlock, so that step is handed to the target's own login session.
- **Briefing rows say what was done, then what it came to.** A row is one sentence — and, only when there is genuinely more worth knowing, up to three short bullets above it. The bullets are plain English about what changed or what was learned, never command lines: the summarizer is *given* the turn's tool calls to write from and told explicitly to write "rewrote the retry loop", not "Bash: npm test". A column of commands is what the terminal one pane away is already showing, and it crowded out the thing the briefing exists to say. With no LLM configured a row is simply the sentence. The parser stays forgiving — bullets first, `•` or `*` instead of `-`, or bullets with no sentence all still produce a usable row.
- **New remote panes use the tailnet address, not the `.local` name.** A pane created from a Bonjour-discovered Mac was addressed by its mDNS name, which is true on that Wi-Fi and false everywhere else — so the pane died the moment you left the building, which is when a remote pane is most worth having. Machines now advertise their tailnet address in the Bonjour record (`ts_host`, read off the interfaces by matching 100.64.0.0/10, so no Tailscale CLI has to be installed), and it is preferred when building the pane's SSH command. The always-on advertiser script publishes it too, and says so if it can't find one.
- **Fixed: a narrow Agent Overview grew a tall column of red letters.** The context-usage pill wrapped one character per line when the header ran out of room, turning a small badge into a stripe taller than the header and unreadable at that size. It keeps its own width now or isn't drawn.
- **Escape closes a peeked overview.** Only for panes with no claim on the key — an overview, a webview, a plugin pane. Escape inside a peeked *terminal* still belongs to whatever is running there, which is the whole reason the shortcut didn't exist before.
- **Fixed: ⌘C and ⌘V did nothing in the Command Center and Overview reply boxes.** A terminal surface answers `performKeyEquivalent` for its whole window, not only when it holds focus, and it claims those two for the terminal's own copy and paste — so a reply box could be typed into but never copied from or pasted into. While a box has focus, the editing shortcuts are relayed to it from a key monitor, which runs before the terminal gets a say; nothing changes about the terminal's own shortcuts when it is the thing you're using.
- **A new Agent Overview shows the conversation, not the tool strip.** Recent Activity is off by default now, alongside errors. The overview earns its pane by being *read* — what you asked, what the agent said, what it needs from you — and a list of commands pushed that down to make room for something the terminal underneath already shows. Sessions outlive the UI process, so this is how you find work that is still running but no longer visible in any window: after a hang, a crash, or an autosave that lost its layout. Previews are read-only snapshots (`zmx history`) — the browser deliberately never attaches to a session just to display it, since attaching is what would steal it from whichever window already owns it. The scan fans out across cores, so a few dozen sessions load in a fraction of a second. **Restoring a session no longer comes back frozen.** Only a zmx session's *leader* client may resize the pty, and upstream zmx promotes a leader solely on user **input**. A pane restored into a session whose previous client had disconnected therefore attached to a leaderless daemon, sent its geometry, had that resize dropped on the floor, and rendered at the stale size — dead to further resizes until someone typed into it. The daemon now claims vacant leadership at connect time (`vendor/zmx`, recorded in `vendor/zmx/UPSTREAM`), so the restored pane's first resize lands; typing still moves leadership as before. **Opening a session that is already on screen also reveals its existing window** rather than adding a second client to it.
- **Fixed: the Session Browser pinned a CPU core while open.** The session tiles were laid out with a `LazyVGrid` inside a `ScrollView`. A lazy grid is a lazy stack of lazy rows, and inside a scroll view each has to estimate the size of tiles it has not built yet while `ScrollViewUtilities.contentFrame` feeds those estimates straight back as the proposal — the two never converged, so SwiftUI re-ran sizing every frame for as long as the browser was on screen. The grid is now built from plain stacks: a window's panes are a handful of tiles, so laying them out eagerly is cheap and always terminates. - **Reload Latest UI**: New menu item **trm → Reload Latest UI** (Cmd+Shift+R) swaps trm into the freshly-installed binary with no perceived lag and without losing your windows. Rather than quitting and relaunching (which leaves the screen empty while the app boots), it does an **overlapped handoff**: the new instance launches *first*, attaches to the same live zmx session daemons, and only once it reports its windows on screen does the old process exit. Because zmx is multi-client — the same mechanism behind `trm mirror` — both UIs briefly render the same PTYs, so there is always something on screen and the underlying shells, agents, and long-running commands never stop. This turns rebuild → `scripts/reinstall-trm.sh` → Cmd+Shift+R into a one-keystroke dev loop, the practical substitute for hot-reloading the UI. The two resources that can't be double-owned are handled explicitly: the successor starts with `[text_tap] enabled = false` (Text Tap's `start()` unlinks any existing socket file, so an eager bind would steal the socket from the still-live predecessor and drop its connected hook clients) and takes the socket over via the new `termania_text_tap_start` C API once the predecessor exits; meanwhile the outgoing process stands down its 30 s checkpoint timer so it can't clobber the handoff state while tearing down. The handoff config also carries the window's frame in a `[window]` section (`x`/`y`/`width`/`height`), applied as the successor window's `defaultSize` — *before* its panes attach, so the terminal is the right size from the first byte and no resize ever reaches the PTYs. (Opening at the default size and resizing afterwards corrupted the display: a TUI mid-render — an agent's prompt, a pager, an editor — painted at the wrong width and was then reflowed, leaving duplicated and interleaved lines. Resizing *before* the panes attach is not an option either: `restoreLastSession` documents that a synchronous `setFrame` during init can deadlock when the IO mailbox fills before the IO thread's event loop is running.) The frame is applied without animation, and pane-move animation is held down across the swap: `buildCurrentConfigToml` serializes the layout but not the geometry — that normally lives in the autosave manifest, which a `TRM_CONFIG` launch never consults — so without it the reloaded window opened at the default size instead of replacing the one it took over from. If the successor never reports ready (crash, refused launch), the old UI exits anyway after 20 s rather than stranding a duplicate. Reload is refused up front — with nothing launched and nothing closed — when it couldn't restore cleanly: session persistence off, panes not backed by live daemons, or invoked from a `trm mirror` window, which doesn't own the layout checkpoint. The confirm-quit prompt is skipped, since choosing reload is already the confirmation.
- **Server-backed UI by default (disposable trm)**: `session_persistence` now defaults to **on** — every pane runs under a zmx session daemon, window layouts checkpoint automatically every 30 s (not just at quit), and at launch trm **re-attaches instantly with no dialog** when the saved layout is fully backed by live daemons. Kill the app — even `kill -9` — relaunch, and everything is back with processes untouched, tmux-style. Set `session_persistence = false` in trm.toml for the old in-process behavior. New CLI: **`trm mirror`** opens a second UI attached to the same live window (zmx multi-client — verified: both UIs stream the same PTYs, either can be killed freely), and **`trm attach-remote <ssh-host>`** opens a local, GPU-rendered trm showing a remote machine's window with panes attached over SSH. Explicit `TRM_CONFIG` launches that only attach to live daemons also skip the startup dialog. Architecture + remaining work: `docs/server-backed-ui.md`.
- **Detachable sessions (tmux-style persistence)**: With `session_persistence = true` in trm.toml, every terminal pane runs under a per-session daemon (powered by a bundled, vendored [zmx](https://github.com/neurosnap/zmx) built against trm's own ghostty-vt). Quitting or closing trm only *detaches* — shells and running processes keep going in the background, and relaunching reattaches with the terminal state replayed. Explicitly closing a pane kills its session; "Terminate All & Quit" kills everything. Sessions can also be attached from any terminal (`trm attach <name>`), shared by multiple clients simultaneously, or attached remotely over SSH (`ssh -t host /Applications/trm.app/Contents/MacOS/zmx attach <name>`). At startup, trm offers to attach any running sessions that no saved window references. New CLI: `trm sessions`, `trm attach <name>`, `trm kill-session <name>`. Detach from an attached terminal with `ctrl+\`. (The previous half-built `trm-server` daemon scaffold — which pointed at a binary that was never built — has been removed.)

- **Quick Terminal Here**: New menu item `File → Quick Terminal Here` (Cmd+D) toggles the Quick Terminal; when opening a fresh shell, it starts in the focused trm pane's current working directory instead of `$HOME`.
- **Watermark hover shine**: Moving the mouse into or out of a pane triggers a single watermark flash — the same highlight animation used when a pane gains focus. Works for both regular and stacked sub-panes.
- **Tap a pane's bar to expand it**: Single-clicking the grab handle at the top of a pane (the bar revealed when you hover the pane's top edge), or a stacked sub-pane's grip bar, now peeks (expands) that pane to half the window width at full height so you can see more of its contents. Click it again — or the dimmed background — to put it back. Dragging the same handle still moves/stacks the pane.
- **Cmd+click to peek a pane**: Holding Cmd and clicking anywhere in a pane now peeks (expands) that pane to half the window width at full height, the same overlay as tapping its grab bar. Cmd+click the pane again, or click the dimmed background, to put it back. The click is consumed, so the terminal never sees a stray mouse event.
- **`surface.list` pid field**: Each surface entry now includes a `"pid"` field with the child process ID of the pane.
- **Startup session dialog**: trm now shows a dialog at launch whenever there is an auto-saved session to restore. The dialog shows the pane count, process list, and save timestamp. When `--config` was also passed, a third button lets you open that file instead. Previously the dialog only appeared when both an autosave and `--config` were present.
- **`start-claude` script**: `scripts/start-claude.sh` launches trm with a multi-pane layout and automatically starts Claude Code in the last pane, then focuses it after a configurable delay (default 3 s). Options: `--panes N`, `--delay S`, `--session PATH`, `--no-focus`.
- **Claude session**: `sessions/claude.toml` — a 2×2 grid session where the bottom-right pane auto-starts `claude`.

### Performance

- **Live Summary no longer reads full scrollback**: The Live Summary poll (every 8 s when enabled) read the *entire* scrollback of every pane on the main thread, hashed it, and sent it untruncated to the LLM. It now reads only the visible viewport — the same pattern the output scanner already used — eliminating a main-thread stall and the risk of re-introducing the full-scrollback leak.
- **LLM pane context reads viewport only**: `buildPaneContext()` (command palette AI) read each pane's full scrollback even though the system prompt only keeps the last 30 lines. It now reads the visible viewport.
- **Context usage tracking is O(1) per update**: The 1 Hz context-usage poll re-scanned the entire snapshot history on every change and re-encoded the full history JSON on the main thread every ~10 s. Aggregates are now bumped incrementally (full recompute at most every 5 min), history saves are time-throttled (≥60 s apart) and encoded off the main thread, and in-memory snapshots are capped at 50k entries.
- **Claude prompt pill: one process scan per tick, app-wide**: Each window's `ClaudePromptPlugin` enumerated every PID on the system (hundreds of syscalls) every 3 s. The scan result is now cached app-wide with a 2.5 s TTL, so N windows cost one scan instead of N.
- **Text Tap accessor polls throttled**: The C-API status accessors (`termania_text_tap_is_active`, `..._app_name*`, `..._client_count`, `..._active_panes`) each ran a full socket poll (accept + per-client read syscalls) and are called per pane per SwiftUI render pass. Accessor-driven polls are now throttled to at most one per 100 ms; the main event-loop poll is unchanged.
- **Keybinding trace logs downgraded**: Leftover `[newtab-trace]` `log.info` calls on every keybinding action (per-keystroke formatting + log I/O) are now `log.debug`.

### Fixed

- **Restored sessions came back pivoted (columns as rows)**: A window saved as a row of panes could restore as a column. `row_cols` is only serialized for jagged/stacked grids, so a uniform grid round-trips through `rows`/`cols` alone — and when the live `gridRowCols` had drifted from the visual pane count, the checkpoint fell back to recomputing the shape from `activeGridConfig`, which is the *launch-time* config and goes stale the moment panes are added, closed, or rearranged. A 3-across window opened from a `rows=3, cols=1` config was therefore written out as `[1,1,1]` — a 3-tall column. The reconciliation now grows or shrinks the layout's *live* shape (widening or trimming the last row) instead of reshaping from unrelated dimensions, so orientation is preserved and a restored window looks exactly like the one that was saved.
- **Agent Overviews lost their group, order, and size on reload**: Four separate breaks in the same seam, each exposed by overviews becoming stackable. The serializer never wrote `stack_group` for an overview (every other pane type did), so a stacked overview came back detached. `restoreStackGroups` counted `agent_overview` entries as *plugins*, which both lost their group and shifted every later pane's index — sweeping unrelated panes into the wrong stacks. Stack restoration ran before overviews existed, so they couldn't join their groups; they now join in a targeted second pass that leaves already-correct groups alone. And because `stackPane` always appends at the bottom, an overview saved *above* its terminal always came back below it — restore now records each overview's saved position and slots it back, transferring host identity when that position is 0.
- **Reordering a stack reset every sub-pane's height**: `moveSubPane` and the drop-to-reorder path both discarded the group's height fractions outright, so any resizing was silently undone by a reorder. Heights now travel with their pane. (`moveSubPane` also cleared the fractions and then tried to read them back one line later to hand to the new host — always nil.)
- **Agent Overview stuck on "Waiting for the pane's working directory"**: With session persistence on (the default), a pane's child process is the `zmx attach` *client* — it has no children and its cwd is wherever trm was launched from, not the project directory. Both of the overview's lookups went through that pid, so the working directory resolved to `$HOME` and the agent process-tree walk (`children[shellPid]`) always came back empty, leaving the overview permanently waiting. The real shell runs under the zmx *server*, reachable via the session socket rather than by walking down from the pane: `ZmxSessionManager.serverShellPid(session:)` asks who holds the socket and takes its first child, and both the cwd and the agent walk now anchor there (falling back to the old path when a session has no live server).
- **Agent Overview drag started but couldn't be dropped**: An overview is pinned to its terminal, so that cell is the *only* valid drop target — and the target test compared against `GridPane.id`, which for a stack reports its *first child's* identity. Whenever the anchor terminal was stacked, nothing would accept the drop and the drag died on release. `validateDrop`, `performDrop`, and `placeOverview` (three separate copies of the same check — the first two agreeing but the third not was why a drop could highlight and still silently fail) now test whether the target cell *contains* the overview's terminal surface, handling plain and stacked cells alike. The overview's **own cell** is now a valid target too: dropping it back onto itself to pick a different side is the natural gesture and previously did nothing.
- **Reload killed panes (and looked like a lost row)**: Reloading could spawn *several* successor processes — four launched within nine seconds in one observed case. Every successor attaches to the same zmx daemons, so each redundant process closed its panes' PTYs as it tore down, sending EOF (`0x04`) to the shells; the daemons logged `shell exited`, tore down their sessions, and the panes closed with `processAlive=false`. This read as the layout dropping its last row, but the panes' *processes* were being killed. Three causes, all fixed: the ready announcement ran from `applicationDidBecomeActive` (which fires on every reactivation, not just launch) and is now made exactly once; the `TRM_RELOAD_PREDECESSOR_PID` marker is cleared once consumed, so a successor is never mistaken for one again; and the reload action now refuses to start while a handoff is already in flight. Reload also validates the *handoff config itself* for dead sessions rather than only the autosave — the two are built separately, so a pane whose daemon had died could pass the autosave check and still be written into the handoff, where `zmx attach` exits instantly and the pane closes.
- **Restoring a session collapsed a row**: A checkpoint containing an agent overview came back with one fewer row — a two-row window flattened into one. Two compounding causes, both fixed. First, agent overviews are created late in restore (they need their terminals to exist), but the seeded `gridRowCols` already counts their cells — so the `reconcileGridRowCols()` that runs right after the terminals are built saw more cells than panes and trimmed the difference, turning a saved `[5,1]` into `[5]` before the overview was ever placed; it now holds cells for overviews still pending. Second, `showAgentOverview` then claimed a cell unconditionally, which is right when opening an overview interactively but double-counts when replaying one from a checkpoint; the claim is now conditional on the grid actually being short a cell, so both callers are correct without either needing to know which case it is.
- **Pane drags broke while pane-move animation was on**: The grab bars are AppKit `NSDraggingSource` views hosted inside the pane cell the grid animates, and an animating layer underneath an in-flight dragging session breaks the drag — which regressed dragging the agent overview by its grab bar. Both drag sources (pane and overview) now hold pane-move animation down for the duration of the drag and release it after the drop's layout change lands, so the pane appears in its new slot rather than sliding into it.
- **Agent Overview ignored the pane-move shortcuts**: Moving an overview with the normal move commands did nothing visible — the generic path reordered the grid, then `repinAgentOverviews()` immediately snapped the overview back beside its terminal. An overview only exists relative to its terminal, so a move now changes its *placement* around that terminal (left/right/above/below) instead of reordering the grid, matching what dragging its grab bar does.
- **Agent Overview took over a neighbouring pane**: Opening an overview displaced an existing pane instead of claiming its own cell. Appending to `agentOverviewPanes` grows `gridPanes` by one, so the `ensurePaneDisplayOrder()` inside `applyOverviewPlacement` saw a count mismatch and rebuilt the display order with the overview already in it — at which point `placeCompanion` treated it as an existing cell, removing it from one row and re-inserting it beside its anchor for a net-zero change to `gridRowCols`. The grid was left with one more pane than cells, so a pane got pushed out. The overview now explicitly claims a cell before placement, keeping cell count and pane count in step.
- **Panes now animate to their new position**: Moving, swapping, reordering, or stacking a pane — and an agent overview claiming its cell — slides the pane into its new slot with a spring animation rather than teleporting. Animation is keyed on each cell's computed geometry and suppressed while a divider is being dragged, so live resizing still tracks the cursor exactly (`PaneDivider` gained an `onDragEnded` callback to signal drag completion).
- **Context usage pill appeared in every window**: The Claude Code context reading is stored process-wide, but each window polled it and rendered the pill unconditionally — so a fresh window with no agent in it showed the context usage of an agent running in a *different* window, and the pill never disappeared once set. Context readings are now attributed to a pane: `context_update` accepts a `"pane"` field (`scripts/claude-context-trm.sh` passes `$TRM_PANE_ID`, falling back to the sender's `mark_connected` pane), exposed via the new `termania_context_pane_id` export, and a window only shows the pill for panes it owns. Readings also expire after 30 minutes, so an agent that goes idle stops leaving a stale number on screen. Readings with no pane attribution (older hook scripts) still show everywhere, as before.
- **Invisible stack sub-pane dividers and typing lag**: Stack sub-pane dividers rendered invisibly, and per-keystroke work in hot paths caused typing lag; both fixed.
- **Phantom selection on pane focus**: Focusing a pane no longer creates a phantom text selection.
- **Pane drag bar**: Dragging by the grab bar now uses an AppKit `NSDraggingSource` (the SwiftUI `.draggable` implementation dropped drags); grip-bar drags are reliable.
- **`GridPane.runShellCommand` uses `/bin/sh`**: was `/bin/zsh -lc`, which sourced user login config and broke on some setups.
- **macOS build on Xcode 26.x + Zig 0.15.2**: replaced `libtool` with a custom `MergeStaticLibsStep` and fixed the xcframework output path resolution.
- **Removed the screen_capture plugin pane** (unused; its registry entries and tests are gone).
- **FFI header drift for `termania_pane_info_s` / `termania_cell_s`**: The C header declarations were out of sync with the Zig structs (`termania_pane_info_s` was missing the leading `pane_id` field; `termania_cell_s` had the color-type byte before the r/g/b triple instead of after). Both APIs are currently unused from Swift, so this was latent — but it's the same class of ABI mismatch that previously caused a release-only crash and a multi-GB leak. The header now matches the Zig layout field-for-field.
- **Text Tap send payloads no longer vanish on truncation**: A send payload longer than 1024 bytes could be cut mid-UTF-8-codepoint, making the whole string undecodable — Swift then silently sent `""` while the client had already received `{"status":"queued"}`. Truncation now lands on a codepoint boundary (also applied to notification title/body), and Swift decodes lossily instead of dropping to empty.
- **Text Tap oversized-message resync**: A JSON line larger than the 4 KB client buffer was silently discarded and its tail bytes were then parsed as a fresh (corrupt) message. The server now replies `{"error": "message too large"}` and discards up to the line's terminating newline so the next message re-aligns cleanly.
- **cmux `id` echoed unescaped**: A request `id` containing quotes/backslashes produced malformed JSON in every cmux response. The id is now JSON-escaped once at extraction.
- **Duplicate URLs in the server-URL banner**: The bare `host:port` pattern re-matched the authority inside already-matched full URLs, so `https://localhost:8443`, `ws://` URLs, or URLs with a path (e.g. `http://127.0.0.1:8080/api`) surfaced a bogus second `http://host:port` entry in the banner. Matches contained inside an already-accepted match are now skipped. (Found by re-enabling the Swift test suite, which had been silently broken — see below.)
- **Stale plugin-registry tests**: Removing the `screen_capture` pane left the registry with 9 builtins, but its tests still asserted 10 (and force-unwrapped index 9, aborting the test binary with signal 6). Tests now match the registry.
- **`zig build test` ran xcodebuild against the old scheme**: The build's `xcodebuild test` step still targeted `-scheme Ghostty`, which no longer exists after the project rename to `trm.xcodeproj` — every full test run failed that step. It now uses the `trm` scheme.
- **`zig build test` hung forever**: The "server broadcast to subscribed clients" test set its check socket non-blocking with `fcntl(F_SETFL, ... | SOCK.NONBLOCK)` — but `SOCK.NONBLOCK` is a socket-type flag, not the `O_NONBLOCK` file-status flag, so the fd stayed blocking and the final `read()` (on a socket that never receives data) hung the entire test run. Now sets the real `O_NONBLOCK` (0x0004), matching what `start()` already does.
- **Text Tap queued-command leak on shutdown**: `TextTapServer.deinit` freed the command list but not the heap-allocated strings of commands still queued between the last drain and teardown.
- **`termania_swap_overlay` double-free window**: The overlay swap re-inserted both panes via `put()`; if the second insert failed, two keys pointed at one pane (double-freed on deinit) while the other leaked. The swap now exchanges the stored values in place.
- **Timer/fd leak when a window controller dies without closing**: `BaseTerminalController.deinit` now invalidates the scrollback-snapshot timer and cancels the config-file watcher; previously these were only torn down in `windowWillClose`.
- **Unbounded memory growth (multi-GB leak) — `ghostty_surface_free_text` ABI mismatch**: The Zig export `ghostty_surface_free_text` took a single `*Text` argument, but the C header and all Swift call sites pass two arguments (`surface, &text`). On arm64 the surface pointer was bound to the text parameter, so the deinit ran against the wrong struct and the actual text buffer was **never freed**. Every `ghostty_surface_read_text` call leaked its buffer — and because the `TerminalOutputScanner` reads each pane's viewport on a repeating poll, this leaked ~1.3 MB/min (~6.7 GB over 4 days). The Zig signature now matches the header (`surface: *Surface, ptr: *Text`), so the buffer is freed correctly. Root-caused with `malloc_history` on a live process (1 ALLOC / 0 FREE on the scanner's allocations).
- **Unbounded memory growth (multi-GB leak)**: The periodic scrollback-snapshot timer (every 30 s, per window) read and re-serialized the *entire* scrollback of every pane on every tick — even when nothing had changed and even while the window sat idle. Each full-scrollback read allocated a large heap buffer (hundreds of KB per pane) that accumulated without bound, growing trm's memory footprint to ~10 GB over multi-day uptime. The snapshot now skips a pane whose visible viewport is unchanged since its last snapshot (a cheap, bounded fingerprint), so idle panes cost nothing and a pane is only re-read when its content actually changes. Explicit session auto-save still forces a full snapshot of every pane. Diagnosed with `malloc_history` on a live release process.
- **`surface.focus` RPC**: The `surface.focus` cmux RPC now correctly focuses the target pane. Three bugs fixed: (1) pane ID lookup in `handleFocusPane` fell back to grid index when `paneId` is nil (matching the same logic as `surface.list`), (2) `focusSurface` now always calls `NSApp.activate` so the trm window comes to front even when another app is focused, (3) `TerminalWindowRestoration` skips macOS native window restoration when `TRM_CONFIG` is set, preventing stale surfaces from a prior session from interfering with a freshly-requested config.
- **`surface.list` duplicate responses**: When multiple windows exist and none is the main window (e.g. trm is in the background), only the first (oldest) controller now responds to cmux queries. Previously both controllers responded, producing duplicate surface entries.
- **Crash opening a new pane (Cmd-T) in release builds**: The Zig `Surface.Options` struct was missing the trailing `reconnect_session_id` field that exists in the `ghostty_surface_config_s` C struct (`include/ghostty.h`) and the Swift `SurfaceConfiguration`. When a split inherited its config via `ghostty_surface_inherited_config`, Swift read that field from uninitialized memory past the end of the Zig struct. In ReleaseFast that memory was garbage (a non-nil bogus pointer), so `String(cString:)` called `strlen` on it and crashed with `EXC_BAD_ACCESS`. Debug builds zero-fill `undefined` memory, so the field read as nil and the bug was invisible there. The field is now declared on the Zig struct so the ABI matches.
