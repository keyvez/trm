# Changelog

Versioning: the trm version lives in the `VERSION` file at the repo root
(shown as CFBundleShortVersionString). The **build number** is the git
commit count (`git rev-list --count HEAD`) — monotonically increasing and
unique per commit — stamped into the app together with the commit hash at
build time. Check yours with `trm version` or the About window. Build
numbers below mark the build at which each release's features shipped;
`≈` marks numbers reconstructed from commit dates for releases tagged
retroactively.

## Unreleased

### Added

- **⌃⌘⇧N: another agent where this one is.** ⌘⇧N opens a remote pane in the other machine's home directory, and the next thing anyone does is `cd` back to the project the pane beside it is in and start the same agent again. ⌃⌘⇧N does both: one SSH round trip reads the folder the focused pane's session is in and the agent running in it, and the new pane opens on that machine, in that folder, with the agent's command typed in — flags and all (`--dangerously-skip-permissions`, `--model …`), minus the ones that name a conversation (`--resume`, `--continue`, `codex resume …`), since two agents on one session would write one transcript. Typed, not run as the pane's command, so the shell is still there when the agent exits. From a local pane it goes to the usual remote machine, with a path under your home mapped to the same place under the other machine's. Pressed in a Command Center row's reply box, it opens beside that row's pane and leaves you on the board. In the File menu under New Remote Pane, with Control held.

### Fixed

- **Parking the pane you were in sent focus to the top-left corner.** Focus now goes where moving right would have taken it — the pane beside it, stepping over its overview when that is parked along with it, or at the right edge the next pane in reading order. Parking some other pane from its bar still leaves your focus where it is.

- **Peeking a parked pane put it back in the grid.** On a shelf tile ⌘-click peeks and a plain click restores, and the tile decided which by asking whether ⌘ was down *when the click finished*. On the pane's name that is a third of a second later — the click waits to see whether it is the start of a double-click, which renames — and ⌘ is usually up by then, so the peek arrived as a restore. Whether it happened depended on where the click landed and how fast your finger came off the key, which is why it looked random. ⌘ is now read from the click itself. ⌘-clicking a parked pane's row on the Command Center also restored it before peeking; it now peeks the pane where it is, as the shelf does.

- **File names were being opened as web pages.** `jobs.rs`, `main.py`, `README.md` — any file whose extension is also a country's domain — came out of the link detector as `http://jobs.rs` and so on, and the overview underlined them, listed them as links and tried to photograph each one. A link now has to be written as one: with its `https://`, or starting `www.`.

- **Every pane had two header bars.** Upstream Ghostty draws a hover-revealed "…" strip across the top of each surface for dragging it around its split tree; in trm it sat right under the pane's own bar, the one that grows when you point at it and already drags, peeks and parks the pane. The "…" strip is gone for good: its file is deleted, and a test fails if an upstream merge brings it back.

## 0.4.0 (build 14554)

### Added

- **Arrow keys move focus around the grid.** ⌘[ and ⌘] step through the panes, ⌥⌘ and an arrow move one cell in that direction — the bindings have always been there, and until now they did nothing in a trm window. Two reasons, stacked. The first: the action was being *dropped*, by a line in the app's action switch reading `break // Split navigation removed — using grid layout`. It was true when it was written — trm had just replaced ghostty's split tree with a grid — and it left two bindings that travel all the way from the keyboard through the core to the app and then stop. The second is why simply re-enabling it would not have helped: the action is Ghostty's `goto_split`, which navigates the *split tree*: the structure panes are stored in, which remembers the order they were created in rather than where they ended up after being moved, stacked and parked. Asked to focus the pane to the left, it would either land somewhere unrelated to the arrow or decide there was no neighbour and do nothing at all. The grid answers for itself now, from the thing on screen: the display order and the per-row cell counts. Rows may be ragged, so moving up or down from a column a shorter row doesn't have lands on that row's last pane rather than refusing to move. At an edge the key is deliberately left unconsumed and reaches the terminal, because ⌥⌘← in the leftmost pane is a keystroke a shell may want. An overview or a plugin pane takes the selection instead of keyboard focus, which is the only thing it can hold.

- **⌃-click a pane's bar to park it.** Sending a pane to the shelf was a menu item and a keystroke, neither of which is where your hand is when you decide to do it — you are usually pointing at the pane. The bar across the top of every pane already is the pane's handle: drag it to move the pane, tap it to peek. ⌃-click now parks it. The bar refuses the context menu while control is held, because AppKit walks up the view hierarchy looking for one and would otherwise show the cell's menu while the pane stayed exactly where it was.

- **The shelf says what a pane is running instead of drawing it.** Tiles used to render the pane's whole viewport in three-and-a-half point type. It was honest — same characters, same colours, the shape of the output preserved — and it was unreadable: a grey smear that says "a terminal" rather than which one, redrawn from four thousand cells per pane per second. A tile is now the name, what the agent last said, and the line the terminal keeps about itself: the command it is running. That is the thing that tells one shell from another, which was the miniature's whole job, and it does it in a tenth of the space. The cell-accurate renderer stays where it earns its keep — the diff inside a Command Center question, where the colours are the content.

- **Rename a pane from the shelf: double-click its name.** The Command Center has had this since it grew a watermark chip, and the sidebar — which is the other place every pane in the window is listed by name — did not, so renaming a parked pane meant bringing it back to the grid first. Double-clicking the name turns it into a field, seeded with the pane's own watermark rather than the label: the label falls back to the worktree, the agent or the folder and carries the worktree insignia when there is one, none of which is text anyone typed. Return renames, esc leaves it alone, blank clears it, and clicking away commits rather than discards — the shelf moves under you as panes come and go, and losing a name to a stray click elsewhere would be its own bug report. Both gestures sit on the name itself so the tile's own click, which restores the pane to the grid, cannot fire on the way to a rename. There is a **Rename…** item in the tile's context menu too, since a gesture nothing tells you about is a gesture nobody uses.

- **The Command Center shows the question an agent is asking, with what it is asking about.** An agent that stops to ask "may I run this" or "may I make this edit" is the most urgent thing on a board and was the one thing the board could not see. Those prompts are drawn and answered entirely in the terminal and never reach the transcript at all; `AskUserQuestion` does reach it, but only once the turn moves on — so both kinds arrived at the board at the moment they stopped being questions. **The question is now read off the pane's own screen.** A row with one shows the question, the choices as buttons, and — this is the half that makes it answerable — **the preview above it, drawn from the pane's actual cells**: the diff in its own greens and reds, the plan, the command about to run. "Do you want to make this edit?" is not a question anyone can answer from a board; the same words over six lines of the real diff is a decision you can take from a phone. Clicking a choice sends that digit to the pane and nothing else — no Return behind it, which would land in whatever the agent draws next and submit an empty message there. The detector is deliberately hard to please: two or more consecutively numbered choices, at the bottom of the screen, with the cursor resting on one of them. That last rule is what separates a menu from the numbered list an agent writes when it reports three things it fixed, and it doubles as the liveness test — the cursor is drawn by the menu that is taking input, and what is left after an answer is the echoed choice without it. Anything less certain and the row shows what it always showed. The same question, its options and a text preview go to the phone, which can answer it back.

- **`[remote] host` in `config.toml`: the machine remote panes go to, written down once.** New Remote Pane and the remote quick terminal picked the destination used last, falling back to whatever single trm was advertising on Bonjour — both inferences with a shelf life. The last-used destination is overwritten the moment you open a pane somewhere else, and Bonjour advertises the address a machine is answering at today, which on a laptop is a DHCP lease; a machine you deliberately reached by its tailnet name would be back to an IP within the week, and then to a *stale* IP. `[remote] host = "you@machine.tailnet.ts.net"` outranks both, prefills the host prompt, and is inherited from the global config by projects that have a `trm.toml` of their own — like the LLM credentials, it belongs to the person rather than the project.

### Fixed

- **Probing a machine that wasn't answering made it answer less.** A Mac with a dozen remote panes open sits near a limit nobody documents: macOS launches `sshd` through launchd with a hard cap of 42 concurrent instances, and past it connections are accepted and immediately closed — which reaches the other end as `Connection closed by <ip> port 22` or `kex_exchange_identification: read: Connection reset by peer`, during key exchange, before authentication, so it looks exactly like a broken host rather than a full one. trm then made it worse from both ends. The issue-tracker's pane discovery recorded a *failed* probe twenty seconds in the past against a thirty-second cache, so an unreachable host was retried every ten seconds instead of every thirty — the rate tripled precisely when the slots were gone. And the cache was keyed by the destination *string*, so one machine reached three ways — an IP, a tailnet name, an `~/.ssh/config` alias — was three separate probes of the same Mac on every cycle. Failure now backs off (a minute, two, four, eight, then a quarter of an hour, cleared by any success), and a destination is resolved through `ssh -G` to the account and address it actually reaches, so the spellings collapse to one probe. A machine that comes back is still found within a minute. The remaining halves of this are yours to configure: `ControlMaster` in `~/.ssh/config` turns a dozen panes into a dozen channels on one connection, and `MaxSessions` on the far side has to be raised to match.

- **A new window came up as a copy of the one you were in.** File → New Window, ⌘⇧N, "New Window" in the startup dialog — all of them rebuilt the entire grid you were already looking at: fifteen panes, their directories, their commands, a second agent started in each. It looked like a session restoring itself for no reason, and after a **Reload Latest UI** it was exactly that. A window opened with no layout of its own falls back to the app-wide config, and the app-wide config is whatever trm was *launched* with — which, after a reload handoff or a `--config` launch, is a snapshot of a whole session written seconds earlier. That snapshot describes the window it was written for. It now seeds exactly one window: the first. Every window opened afterwards without a layout of its own starts as a single pane, keeping the gap, the padding and the rest of the settings, which are preferences rather than a layout. Windows that are *handed* a layout — a session restore, the Session Browser, a project `trm.toml` opened by path — are untouched, because they never consulted the fallback in the first place.

## 0.3.0 (build 14546)

### Added

- **⌘-click a pane in the sidebar to read it where it is.** The shelf lists every pane in the window with what its agent last said, which answers "which one was doing the migration" — and then asked you to commit to the answer, because the only thing a tile did was focus the pane or pull it back into the grid. ⌘-click now peeks it, the same gesture that expands a pane in the grid or a sub-pane in a stack, and it is worth more here than anywhere: a parked pane has no cell to ⌘-click, so the shelf was the one place a pane could be listed, described, and still unreadable without first giving it a cell back. A peeked parked pane is shown on its own and goes back to the shelf when the peek closes — the grid is not rearranged to look at something, which is the whole point. There is a **Peek** item in the tile's context menu too, since a gesture nothing tells you about is a gesture nobody uses.

- **The machine a remote pane opens on can be changed.** One machine is routinely three addresses — an IP, a `.local` name, a tailnet name — and trm would settle on whichever it saw first and then offer no way back: New Remote Pane skips the prompt whenever exactly one trm is advertising on Bonjour, the remote quick terminal reuses the last destination silently, and neither has anywhere to type a different one. A machine you deliberately reached by its tailnet name reverted to the advertised IP, permanently. Three changes. **Hold Option on File → New Remote Pane** and it becomes **New Remote Pane on…**, which always asks — and what it picks is remembered, so it is how the default machine is changed rather than a one-off. **What you chose now beats what was discovered:** the remembered destination wins over a single Bonjour result, which is a guess at the question being asked and should not overrule an answer. And **the prompt offers every address that machine has answered at**, newest first, alongside the ones being advertised — Bonjour only knows what is on the air right now, which is why a machine reachable three ways was only ever offered one.

- **A Command Center row says what actually happened, not just that something did.** Briefing mode gave each agent one sentence of at most eighteen words and, in principle, up to three bullets under it — in practice almost never, because the model was told to add them *only* if the sentence left something out, and a model asked that question says no. So a row was one short line about a turn in which an agent had edited four files, run the tests twice and hit an error, and none of that reached the board. Worse, the line was frequently about the wrong turn: the stored summary belonged to the message it was written from and stayed on screen while the pane moved on, so a row could be confidently describing work from two turns ago. **Rows now carry their detail, and it is prose rather than a command log.** The summarizer is asked for a sentence of up to thirty words *and* three to five further sentences, each explaining a piece of the work the headline had no room for — what changed and why, what it found, what the numbers were, what the error actually said, what is left and what it plans to do about it — and it is told explicitly to write about what came of the work rather than the tools that did it, because "Bash: npm test" is the command and not its outcome, and the terminal one pane away is already showing it. It is also told which state the pane is in (working, blocked on a question, stopped) and what failed, because a summarizer given only the words writes a report on a finished turn even when the agent is mid-tool. Each line gets three lines of room and loses its tail rather than its middle, since a path or an error message with its centre cut out is the part worth reading thrown away. **And a row with no model behind it is no longer a single sentence, nor a list of commands.** When the summary is stale or absent — a new message, a slow call, or no LLM configured at all — the row falls back to the agent's own account of the turn, rebuilt on every scan: what failed and what it said, then the paragraphs the agent wrote under its opening sentence, which is where it puts what it found, what it changed and what is unfinished. Fenced code is left out and list markers come off while their text stays. That fallback cannot describe the wrong turn, because it is built from the turn on screen.

- **The Command Center can take the whole window.** The board lives in a strip along the window's trailing edge, which is right when it is something you glance at beside the work and wrong the moment it *becomes* the work — six agents running, four of them with something to say, and each one's summary squeezed into a 320-point column next to terminals nobody is reading. The panel header has a **full view** button now: the board goes over the entire window, laid out as a grid of cards, with no terminal panes on screen. Press it again, or hide the Command Center, and the panes are back exactly as they were. They never went anywhere — full view is drawn *over* the grid rather than in place of it, so no terminal is resized to a hundred columns on the way in and back again on the way out. The mode is remembered across launches, like the panel itself, and closing the board from full view leaves the window on its panes rather than on a takeover waiting to reappear.

- **The quick terminal can drop down on the remote machine: ⌃⌥`.** The drop-down terminal was always a shell on *this* Mac, which is the wrong machine about half the time — the build, the logs and the agent are on the box you keep a remote pane open to, and reaching a shell there meant finding that window, or opening a pane and typing an SSH command into it. The binding is the quick terminal's own ⌃` with Option added, because these are one gesture with one difference — which computer answers — and it is global for the same reason the plain one is: the shell you want on the other machine is wanted from wherever you happen to be. In the menu it sits *behind* the View → Quick Terminal item rather than beside it: hold Option and the entry becomes **Quick Terminal on Remote**, which is how a variant of a command belongs in a menu that already has one Quick Terminal in it. Rebind it like any other keybind (`keybind = global:ctrl+alt+backquote=toggle_quick_terminal_remote`). It asks nothing in the normal case: it uses the SSH destination trm last used for a remote pane — the same `LastRemoteHost` that prefills the New Remote Pane prompt — so the machine you are already working on is one keystroke away. With nothing remembered, a single trm advertising on Bonjour is taken as the answer, exactly as New Remote Pane treats it; failing that the usual host prompt appears, with the discovered machines listed, and what you pick is remembered so the next drop-down is silent. Closing it never asks anything. What comes down is a real remote pane rather than a shell running `ssh`: the same `zmx attach` arrangement, so the session daemon lives on that host and the shell keeps running while the quick terminal is hidden, while trm is closed, and after this Mac reboots. The session name is remembered per host, so the drop-down comes back to the shell it had — same directory, same half-typed command — instead of a fresh one each time; a link that died between drop-downs is reattached to that same session rather than stacking a second one beside the corpse. And a quick terminal that already has a local shell in it keeps it: asking for the remote machine opens its session alongside, because a shell mid-command is not something a shortcut should take away. Pressing it again when that machine's session is already down there just puts the cursor back in it — and again while it is showing hides it, without asking anything.

- **The Command Center's expanded panel renders the reply, instead of showing the board's summary of it.** A row on the board is one line, so the text behind it is deliberately flattened: `**` and backticks stripped, code blocks dropped, the whole thing cut at 600 characters. Opening the panel gave that same string half a screen — headings arriving as `##`, lists as a column of hyphens, and whatever the agent wrote in a code block simply absent. The panel now gets the blocks the Overview gets, and renders them the same way: headings set as headings, ordered and unordered lists, quotes, rules, tables, and fenced code in a block that copies when you click anywhere in it. The prompt above it is rendered too, and neither is truncated any more. The board's rows are untouched — a wall of cards is for glancing at, and a heading in a one-line summary is noise.

- **A section heading copies when you tap anywhere along it.** The Overview's headings have been copy buttons for a while — the fastest way to take a reply is to tap "Claude said" rather than drag a selection through a narrow scrolling column — but the button was only as wide as the few small words and the 8-point icon beside them, so the obvious place to press, the empty space along the rest of the line, did nothing. The whole line is the button now. The Command Center's expanded panel gained the same headings: tap "You asked", "This turn" or "Claude said" to take that section.

- **Fixed: a message written over several lines arrived as one line.** Everything you write to an agent from trm — the Command Center's row box, the expanded editor where Return deliberately breaks the line instead of sending, the Overview's compose box, the phone — went down the wire with its newlines folded to spaces. The reason was real: an agent's input box submits on Return, so a multi-line message sent as typing would have sent its first line and left the rest behind. The fix is to stop sending it as typing. The text now goes down as a *paste*, which is the same path the terminal takes when you press ⌘V, and a program with bracketed paste on — every agent's input box — receives the whole thing framed as pasted text: the newlines inside it stay newlines, and only the bare Return trm sends a quarter-second later submits it. A paragraph, a list, a stack trace and a diff now arrive in the shape they were written in. A pane with nothing bracketing its input — a plain shell prompt — still gets the message on one line, because there each newline would mean "run this", and a message is not a script.

- **Clearing an agent's context no longer clears its overview.** `/clear` starts the agent's transcript over — Claude Code opens a fresh session file — and the overview started over with it: the turn you were reading vanished mid-read, and so did every way back to any of it. That emptiness is authoritative about what is *live*, and it is right that the reading pane shows the new context. It is not right that the record goes with it: the agent is the one that forgot, and what it said an hour ago is still what it said. The turns are kept and stay pageable exactly as before, with the seam marked — a divider where the memory was emptied, timed, and a note on the turn that opens the fresh context telling you everything older is still here to page back to. Contexts are numbered rather than counted, so a locator that briefly changes its mind about which file a pane's agent is writing (or an agent that exits and comes back) re-adopts the context it left instead of filing a second copy of the same turns behind a divider that never happened. What is kept is capped at the last 300 turns, from the oldest end: this is paging back through recent work, not an archive.

- **Hold a turn arrow for the whole session.** The ‹ › arrows move one turn at a time, which is the right gesture for "what was I just looking at" and the wrong one for "where was that thing twenty turns ago". Press and hold either arrow — or click the turn counter between them — and every turn in the pane drops down as a list: newest first, one line each (what you asked, or failing that what it said, or what it ran), the turn you are on highlighted, and a labelled divider wherever the context was cleared. Pick one and the overview goes there. The long press does not also page a turn on release, which is the sort of thing that is only noticed when it happens to you.

- **Fixed: closing a peek could leave the pane behind it empty.** The pane was not lost — reloading the UI brought it straight back, which is the signature of state that is fine underneath and simply not on screen. A terminal is an AppKit view and an AppKit view has exactly one parent, so peeking a pane does not copy it into the expanded view, it *moves* it there and the grid cell shows a placeholder meanwhile. Handing it back was the fragile half: the cell noticed the surface had been orphaned during its next layout pass and took it in again. But dismissing a peek changes nothing about the cell's size or position, so frequently no layout pass ran, and the pane sat as a dark rectangle with its watermark on it until something unrelated forced a redraw. The hand-back is now *announced* rather than deduced — the expanded view gives the terminal up the moment it leaves the screen, says so, and the cell that owns it takes it back at once. It is announced on the way out of the window as well as at teardown, because SwiftUI can keep a removed view alive for a while and every moment the surface is held by something that is not drawing it is a moment the real cell is empty. The old layout-time check stays as a backstop for a handoff that happens with nobody listening. A peek that is genuinely on screen still keeps the terminal, which is the whole point of the handoff: the test is whether the current holder is on screen, not whether there is one.

- **Fixed: a remote pane's agent did not come back after the *other* machine rebooted.** Bringing an agent back on the conversation it was having worked only for panes running on this Mac, and silently did nothing for remote panes — which is the case that needs it most, since the machine doing the work is usually the one being restarted. Both halves of the feature had quietly excluded them, for the same reason: the hook's record, the transcript and the daemon all live on the *other* machine. Nothing here could be snapshotted at save time without an SSH round trip per pane on the 30-second checkpoint, and worse, `zmx attach` recreates a session that has died, so this side could not even tell that anything *had* died — a remote pane always looked reattached. A restarted host therefore brought back the layout, the directories and the watermarks, and ten empty shells. The far machine is now simply **asked**, at restore rather than at save, once per host rather than once per pane, and the single round trip answers the whole question: which of these sessions is gone, and what was each one talking about. Being asked late is also more truthful than a snapshot — it describes the machine as it is now, not as it was when the layout was last written. A session still running is left strictly alone, since its agent is still sitting in it and typing would arrive as a *prompt* rather than a command. Liveness is a test for something listening on the socket, not for the socket file being there: those files live under `$HOME` and outlive a restart, so a just-rebooted machine is exactly where the file is present and nothing is behind it. And the session name becomes a word in a shell on a machine trm does not control, so it is checked for shape before it travels.

- **Fixed: tapping a code block in the overview didn't copy it.** The gesture had been there all along — the whole block was a click target — but the code text was marked selectable, and selectable text takes the mouse. Clicks landing on the characters went to the selection machinery and never reached the gesture, so the only parts that answered were the padding and the copy icon in the corner: a button the size of a postage stamp on a block the size of the pane. That marking also overrode a decision made elsewhere, since the grid deliberately turns selection *off* for the overview. **Click anywhere in a code block now copies it.** The rule is that a code block is a thing you take whole — a command to paste, a snippet to run — while prose is what you quote a sentence from, so prose stays selectable and code does not. The block also says so before you click it: the background and border brighten under the pointer and the border flashes green on the copy, because a whole-block target you can only find by trying it is not much better than a tiny icon. The cost, and it is a real one: a part of a code block can no longer be dragged out in the peek, where selection used to be on — one line out of forty is now a whole copy and a trim.

- **Left and right page through an overview's turns.** The ‹ › buttons were the only way back through what an agent did earlier, which is a lot of clicking for something you read by walking backwards. **Click an overview and the arrow keys page it.** Clicking selects the pane and rings it, exactly as clicking a terminal focuses one, and the arrows stay with it until something else takes the selection — so reading back through a morning's work is arrow, arrow, arrow, with the pointer wherever you left it. Pointing at an overview still pages it too, which keeps a glance at the pane across the grid free: it pages without taking the selection off the one you are working in. Neither is real keyboard focus, because an overview has no way to hold it — the panes that take focus are terminals, and peeking an overview focuses the terminal beside it on purpose so the agent is ready to type at. Taking the arrows from whatever holds focus would break line editing at exactly the prompt where those keys get used most. They are never taken from a text field either, so the compose box at the foot of a selected overview still moves its caret through what you are typing. The key is only swallowed when that overview can actually move — at the newest turn, right goes back to the terminal untouched — so an overview with nothing to page costs nothing, and modified arrows (⌥←, ⇧←) always belong to the terminal.

- **An AI agent comes back after a reboot, on the conversation it was having.** Session persistence normally means the processes never died: panes run under their own session daemon, so quitting trm — or killing it — leaves the shells running, and relaunching reattaches to them. A restart is the one event that defeats that. Every daemon is gone, so every pane comes back a fresh shell, and an agent thirty turns into a problem is simply not there. But the agents keep their conversation on disk and both take a flag to resume one, so a reboot now restores in a *lighter* way than a relaunch does: the layout, the directories and the watermarks as always, and in place of a live process, **the agent restarted on the conversation it was in** — `claude --resume <id>`, or `codex resume <id>`. The id needed no new capture. The SessionStart hook already records which transcript belongs to which pane, and for both agents the transcript's filename *is* the session id, so the thing worth saving was sitting in a path trm already had; it goes into the session file as `agent` and `agent_resume_id`. Where the hook has not run — an agent already going when it was installed, or a machine where it was never set up — an open Agent Overview has resolved the transcript anyway, and is asked instead. Neither path goes looking on its own, because this runs for every pane on the 30-second checkpoint and resolving a transcript from scratch means scanning directories. The resume is *typed into the shell* rather than made the pane's command, so a resume that fails leaves you at a prompt rather than a dead pane, and the shell is still yours when the agent exits. A pane that reattached to a living session is never sent anything — the agent is already in it. And because the id reaches a shell, it is checked for the shape of a session id at both ends and quoted regardless: a filename that is not one stops there.

- **The quick terminal has a shortcut: ⌃`** (control-backquote), and it works from any app. A drop-down terminal you can only summon from the terminal is a window you already had — the whole point is the thought that arrives while you are in a browser or an editor, so the binding is global. Control rather than the ⌘\` that the documentation reaches for first: macOS spends that on "next window in this app" in *every* application, and taking it system-wide is a large thing for a default to do quietly. Rebind or remove it like any other: `keybind = global:ctrl+backquote=unbind`.

- **Fixed: nothing was highlighted while the reply was being read.** The mark was built the fragile way round — it searched the page for the words being spoken. But the reading is a *rewrite* of the reply: amounts respelled ("$15-45k" becomes "15 to 45 thousand dollars"), code spans named rather than read, links replaced by "a link", line breaks collapsed. Any one of those leaves a sentence that appears nowhere on screen, so the search found nothing and lit nothing, silently — the one failure that looks exactly like the feature not existing. It is structural now: as the reading is assembled, each piece records which block of the reply it came from, so the speaker says *which block* is sounding and the page marks it directly. There is nothing to search for and nothing to fail to find. The mark is a tinted panel behind the whole block, coarse on purpose — the point is to see where the voice is at a glance — and it lands with the first sound rather than half a second later when the first buffer drains. A second defect fell out of testing it: a short reply fits under the segment limit whole, so it was becoming one segment spanning three paragraphs and could only mark one of them — the highlight sat on the first paragraph while the third was being read. Each part of the reading is now cut into segments on its own, so a segment never covers two blocks. Phrases the reading invents — "Then a code block." — belong to nothing on the page and correctly mark nothing.

- **Fixed: an amount in backticks was read as "a value".** Saying `$15-45k` properly was only half the job: agents write amounts inside code spans constantly, and a code span goes through a separate test first — is this a word, or is it machinery nobody can pronounce? A dollar sign made it machinery, and machinery with one word in it is announced as "a value", which is the least useful thing that can be said about the number you are being asked to react to. Figures are now recognised before the machinery tests and spoken: `$15-45k` is "15 to 45 thousand dollars", `45k` is "45 thousand", `10-20%` is "10 to 20 percent". A bare magnitude letter is only expanded inside a span already known to be nothing but a figure — in running prose "3M" is as likely to be three megabytes as three million, and that is not a guess worth making. The spans the old behaviour was right about are untouched: a git invocation is still "a git command", a hash is still "a commit", and a JSON blob is still, correctly, a value.

- **Fixed: "$15-45k" was read as noise.** Seven characters, four problems: a symbol that is spoken *after* the number it sits in front of, a dash that means "to" and not "minus", a magnitude letter that governs both numbers rather than the one it touches, and an order that has to be rebuilt instead of read left to right. Synthesisers guess at this, and guess differently each time — so a figure came out as gibberish exactly when it was the part you were listening for. It is now said as "15 to 45 thousand dollars", and a lone amount moves its symbol too: `$1.5M` becomes "1.5 million dollars", `£200` becomes "200 pounds". Thousands separators go, because "15,000" read as written invites a pause in the middle of one number, and `10-20%` gets its dash spoken as well. Digits stay digits — every voice reads those correctly; only the symbols and the shape are rewritten. Deliberately narrow, because guessing here breaks more than it fixes: a date (`2026-09-11`), a version (`1.7`) and an ordinary hyphenated range (`3-4 minutes`) have no symbol to move and are left exactly as they are, and the magnitude letter has to end a word, so "50 kilometres" is not fifty thousand ilometres.

- **Follow the reading on the page, pick it up where you stopped, and skip by seven seconds.** Three things about listening to a reply. **The sentence being spoken is now marked in the overview as it is read**, so a reading you are half-following has a place on the page rather than being a voice you have lost your position in. This needed the app to take over cutting the reading into pieces — the worker split the text itself, so only the worker knew where the seams were — and every chunk of audio now comes back stamped with the segment it belongs to. Segments are about a sentence or two: a segment is also the unit that lights up, and three sentences at once is not following along, while one sentence alone loses the prosody that carries across a full stop. Within a segment the sentence is chosen by how far through the audio you are against how far through the characters it sits — an estimate, and good to well within a sentence. The mark is found by *looking the sentence up* in what is on screen rather than by counting characters: the reading is a rewrite of the reply, with code blocks named rather than read and markers stripped, so no offset maps one onto the other. A sentence the reading rephrases — "Then a code block." — has nothing to match and quietly goes unmarked. **Stopping is now a pause.** The audio already made and your position in it are kept, so pressing play again carries on rather than starting a four-minute reply from the top to reach the three minutes you had already heard. Cancelling cuts the worker off mid-segment, so the fragment of the sentence it never finished is dropped — otherwise resuming would render that sentence again behind the half of it you already had — which also lands you back on a sentence boundary, which is where you wanted to be picked up. The Command Center's stop button is still a real stop, and throws the reading away. **And the skip buttons move seven seconds rather than ten.** Ten is a music player's number; what you skip back for here is a sentence you did not catch, and a sentence is about seven seconds, so ten put you a sentence and a half back and made you listen again to something you had already heard.

- **The reader takes a tone, and repetition is what earns the frustrated one.** A voice that says "the restore test failed again, that's the fourth time" in the same bright tone it used for "every test passes" is reading words rather than telling you something — and the reason to hear a reply instead of reading it is that you are doing something else, so the delivery has to carry the part you would have taken in at a glance. The reading now goes out with a mood attached. **Frustration comes from repetition**, which is the signal no single sentence contains: failures are grouped by the tool *and the shape of the error* — digits stripped, the opening words kept — so "3 tests failed in 4.12s" and "3 tests failed in 3.80s" count as the same wall hit twice rather than two separate misfortunes. Three of the same failure sounds worn down; three *different* failures is a bad afternoon and reads as concerned; two is a retry, not a pattern. An unanswered question outranks everything else, because being asked something is the only state that is about *you*; being stuck outranks a single failure; a failure outranks good news. The moods are few and deliberately slight — an agent that sounds distraught about a lint warning is worse than a flat one, because you stop believing the tone and then it carries nothing. The voice description itself never changes and the mood is appended to it, so a change of feeling can never become a change of speaker. **This needs a model that takes direction**: the CustomVoice checkpoint clones a named speaker and ignores instructions entirely — the same fact that forces 1.5× playback through a phase vocoder — so set `TRM_TTS_MODEL` to a VoiceDesign model to hear it.

- **Escape on a peek no longer stops the reading — the controls move to the top of the Command Center.** Peeking a terminal opens an overview alongside it, and Escape closes that overview again, which used to take the voice with it: the speaker was owned by the pane and nothing else held it, so dismissing the view deallocated the audio mid-sentence. But Escape means "put this view away", never "stop talking" — you dismiss a peek to get back to your grid, often *because* you would rather listen than read. The reading now outlives the panel it started from, and the **Command Center grows a bar at the top** carrying what a reading needs: what is being read, by name, the scrubber and position, start-again, back and forward ten seconds, the speed, and a stop button. It is drawn only while something is playing. The board is the right home for it — it is the one panel that is about every pane rather than any one of them, which is exactly what a reading with no pane on screen has become. Open that pane's overview again and it **adopts the reading already in progress** rather than offering a play button over audio you can hear: a second press would otherwise have started a second voice on top of the first. The name over the controls is the pane's own watermark, kept current, so renaming a pane mid-reading does not leave a stale label above the stop button. Closing an overview by hand behaves the same way, for the same reason.

- **Fixed: a pane's configured title was dropped on restore, and closing your last window could erase the session.** Two ways a saved session came back less than it was. A `title` set on a pane in `trm.toml` was read when the pane opened and then never written back out — webview and plugin panes round-tripped theirs, terminal panes silently did not — so the name survived exactly until the first save. A pane now keeps the configured title apart from the live one the shell reports, and persists that; writing the live title instead would restore a grid full of panes called "zsh". The second was worse: the autosave checkpoint read "no windows open" as "the user closed everything, nothing should resurrect" and wiped the saved layout. But that check runs on a 30-second timer and again on quit, and both routinely observe zero windows for reasons that are not a decision — the last window closed a moment before quitting, the timer ticking between windows — and the snapshot went either way, which is why reopening came back blank. A checkpoint that finds nothing to record now records nothing and leaves the last good snapshot alone. Wiping stays an explicit gesture: **Terminate All & Quit** still clears it.

- **A session comes back in the window it was saved in, and a new window opens at the size you work at.** Restoring a session put the grid, the watermarks and the panes back — into a window at the built-in default size, which is small enough that a 2×2 grid renders four unusably tiny panes. So the first thing every restore asked of you was to resize the window you had just asked it to bring back. The frame was not so much lost as never written: it lived only in `_autosave_manifest.json`, which named sessions and the single-window fallback do not write. Session TOML now carries a `[window]` section — `x`, `y`, `width`, `height` — saved with the layout and applied at the one point every restore path funnels through, so named sessions, `_autosave_last.toml` and the manifest all get their frame back from one place rather than three. Size and origin are separate keys, so a project's hand-written `trm.toml` can ask for a size without pinning the window to one spot on one display; a window given a size but no origin still cascades, since inheriting the previous window's exact origin would stack them. A frame that no longer lands on any screen — saved on a monitor you have since unplugged — is pulled back to the middle of the main one, because a window restored off-screen is indistinguishable from the app failing to launch. And a brand-new window with no session behind it opens at the last size you resized or moved a window to rather than the default; fullscreen and miniaturized frames describe the screen rather than a choice you made, so they are not what gets remembered.

- **Fixed: stopping a reading meant the next one wouldn't play.** Press play on an overview, stop it a second later, press play again — and nothing happened, for as long as the reading you had abandoned would have taken to finish. The voice worker renders one request at a time and does not look at the next line of its input until the current one is done, and stopping playback only ever dropped the app's *end* of the stream: the worker carried on synthesising the whole reply into a void, and the second request sat unread in the pipe behind it. Nothing was broken, so nothing said anything; it simply did not start, which for a four-minute reply is indistinguishable from a dead button. Stopping now tells the worker to stop, and the worker can hear it: stdin is read on its own thread so a cancel can arrive mid-render, and the render loop checks between chunks rather than between requests — so a cancelled reading stops within about half a second of audio instead of running to the end, and the next press of play starts immediately. A cancel that arrives for a request still queued means it never starts at all. Measured against a stubbed synthesiser: the abandoned reading used to run all thirty of its chunks and now stops after the one already in flight.

- **The expanded Command Center pane is two equal halves.** Open a row into its editor and the panel divides down the middle: what the agent said above, what you are writing below, the same amount of space each. Neither is the junior partner — an editor given the lion's share leaves the message it is answering in a letterbox, and a message given it puts the cursor at the foot of the panel. The halves are measured, not negotiated, and keep a floor so a short panel scrolls its sections rather than splitting into two useless slivers. **The summary half says a great deal more than the card did.** A card shows one paragraph because it is one of many on a wall; here there is only this agent, so it carries the state it is in, the line that says something wants a decision, *what you last asked* in full rather than clipped to two lines — re-reading the question is most of why you opened the panel — *what it actually did this turn* as the turn's tool calls, the reply itself, selectable, and the links it printed. Each block is captioned, so the half reads as sections rather than one run of grey monospace.

- **Fixed: going to a pane from the Command Center did nothing while a peek was open.** Tapping a row's watermark focuses that pane — but a peek covers the grid, so focusing a cell underneath one changed nothing you could see: the pane you asked for stayed hidden behind the one you were already reading, and the tap looked broken. The peek is now put away and the pane itself is shown. Moving the peek to the new pane was the first answer and it was the wrong one: a row names a *terminal*, and peeking a terminal brings its overview along — so asking for a pane got you a wall of text beside it, or, where the pair could not be resolved, the overview on its own and no terminal at all. The tap means "show me that pane", so it shows that pane. A row whose pane is already the peeked one keeps its peek and just takes focus — you are looking at it already. The "is this surface peeked" test — which has to count an overview peeking alongside its terminal as the same thing on screen — is one check shared with the grab handle rather than two copies.

- **End a pane from the Command Center.** Right-click any row — card or briefing tile — and **Exit Pane** closes that pane for good. The board is where you find out an agent has finished, or wedged, or was never worth starting, and until now noticing that and acting on it happened in two different places: you read the board, went to the pane, and closed it there. It goes through the same `closePane` the grid cell's own menu uses, so a terminal still asks before it is killed — a right-click and a slip must not end a running process — and the item is destructive and alone in the menu, because the other things a row can do are already a click away on the row itself. The row disappears when the pane does. It cannot simply remove itself, since the confirmation may still come back "no", and waiting out the board's 2.5-second scan reads as a close that did not work; so after a close is requested the board looks again four times a second until the pane has left its window, for up to ten seconds, and falls back to the ordinary scan for a confirmation left sitting open.

- **Rename a pane from the Command Center, and double-click a row's header to go to it.** The board is where you read pane names, so it is where you notice one is wrong — and getting to the pane, renaming it there, and coming back was three moves to fix a word. **Double-click a row's watermark** and the chip becomes a field: Return renames the pane, Escape leaves it alone, and a blank name clears the watermark, exactly as the pane's own rename does. Clicking away commits rather than discards — this is a field in a list that moves under you, and losing a name to a stray click elsewhere on the board would be its own bug report. The field is seeded with the pane's *own* watermark rather than the label on the row, because the label can carry the worktree insignia or fall back to "pane 3", and neither is text anyone typed or wants to edit around. The row re-reads its label immediately rather than wearing the old name until the next scan. **Double-clicking the row's header** — the nameplate the watermark sits in — goes to the pane and puts the keyboard in it, which is what double-clicking a nameplate does everywhere else in trm; a single click anywhere on the row still opens its reply box, and ⌘-click still opens the Overview. Both work on cards and on briefing rows. Panes that are not actually here — a remote agent's row with no local pane to stamp — decline the rename rather than quietly putting someone else's name on the first cell in the grid.

- **Open a Command Center reply box into a full editor.** ⌘-click the box (or the expand button beside it) and that row **takes the whole panel** — the other agents step aside — with the row you are writing to at the top, what it said under that, and the rest of the panel as an editor where **Return breaks the line instead of sending**. Nothing leaves until ⌘↩ or the Send button. **Escape puts the board back**, keeping what you wrote. Taking the panel rather than growing the card is the point: the board is a live feed whose rows move as agents speak, and writing a paragraph inside something that rearranges itself underneath you is unpleasant in a way that a bigger box does not fix. One row at a time, for the same reason — this is not a thing you do out of the corner of your eye. The agent's message stays on screen above the editor, bounded and scrollable within its bounds, so an agent that just wrote six paragraphs cannot push the editor off the panel; and a pane that closes while you are writing to it drops you back to the board rather than leaving an editor addressed to nothing. The one-line box is the right shape for "yes, go ahead" and the wrong one for a paragraph with a list in it, where every Return fired off half an instruction and left the rest behind. ⌘-click is the gesture the rest of trm already uses for "show me this properly" — on a card it opens the Overview, on a pane it peeks. Escape closes the editor rather than the panel, one level at a time, and the draft stays where it was; the arrow keys move through what you are writing rather than walking the message history, which is what they do in the one-line box and would be indefensible mid-paragraph. In the grid and briefing layouts the card grows to hold the editor rather than cropping it: every card being the same height is what makes the board scannable, but the card you are typing in is the exception worth making. The editor says plainly that line breaks become spaces when sent, because an agent's input box submits on Return — the message goes as one line however many you wrote it on, and that is not something you can find out after sending.

- **Fixed: the Reconnect button was missing from a peeked pane.** A remote pane whose link dropped holds its last frame under a scrim with a Reconnect button over it — in its grid cell. Peek that pane and the peek draws its own copy of the terminal, without the overlay, over a scrim that hides the cell's; so the one gesture you reach for when a pane looks wrong was the one place the button could not be found, and the pane looked simply dead. The peeked terminal now carries the same overlay. Reconnecting from inside a peek also used to leave you staring at an empty scrim: reattaching replaces the pane's surface, and the peek still pointed at the old one, which resolves to no pane at all. The peek follows the swap now, so you keep reading the pane you asked to keep reading.

- **Cards lay out as a grid when there is room for one.** One column in a narrow grid cell, two or three in a peek — the overview is the same view at 300 points wide and at 1,000, and a single column of cards across a wide peek wasted most of it while pushing the last card off the bottom. Cards are dealt across the columns in order, so reading left-to-right still reads them in the order they were built: for an agent that is the order a reply is written in, and for a shell it is command, summary, failure, output. The columns are independent stacks rather than grid rows, because card heights differ by an order of magnitude — a three-line command card beside a forty-line output card would leave a hole the size of the taller one. Deliberately not a lazy container: a handful of cards is cheap to size eagerly, and lazy stacks inside this ScrollView are what once pinned a core estimating heights they had not built.

- **The overview works on panes that have no agent in them.** It used to say "No coding agent found in trm." and stop there, and peeking a plain shell opened nothing at all, on the reasoning that an overview of a shell has nothing to show. It has the same thing to show: a shell is a conversation with the same shape — you type something, it answers — so the pane's scrollback is read back into that shape. Every command is a turn, its output is that turn's reply, and the ‹ › arrows page through them exactly as they page through an agent's turns. Nothing marks where a command starts (there is no shell integration to lean on: `zmx history` returns rendered text with the OSC marks long gone), so the prompt is found by what it looks like — the marker that repeats down the window wins, which is what keeps a `$` in a docs snippet or a `93%` in a status line from inventing commands that were never run. Themes that keep printing prompt *after* the marker are handled, because the one on this machine does: oh-my-zsh's default draws `➜  trm git:(main) ✗ ` and without that the first command read as `trm git:(main) ✗ git status`. The branch segment and the dirty flag come off by rule; the bare directory needs the repetition test, which only drops a repeated first word when it also names a place, so someone whose every command starts with `git` does not lose the word. A pane sitting inside one long-running program — a dev server, a `tail -f`, an installer — has no prompt anywhere and is read as that one unfinished thing rather than as nothing.
- **What failed, pulled out of the log.** A command's output is scanned for the lines that report a failure — a compiler `error:`, `fatal:`, a traceback, `command not found`, `npm ERR!`, and the usage complaint a CLI prints when it was called wrongly, which rarely contains the word "error" and always means the command did not run. The lines that mean the opposite are deliberately not matched: `0 errors, 3 warnings`, `no errors found`, and anything starting with `warning` — a filter that flags everything flags nothing. Above the reply are three copy buttons: the full log, this command with its output, and **the error with the lines around it**, which is the one worth having, since an error line on its own rarely says which file or target it came from. The last twenty lines are a fourth, for when nothing failed and you just want what it said. All four are in the overflow menu too, for a pane too narrow to show them.
- **Cards for a command.** In card mode a shell command becomes what was run and what kind of work it is — build, tests, version control, packages, run, search, remote, containers, files — then how it went, then what failed, then the output. The summary leads with the failure when there is one and otherwise with the line the tool itself printed about how it went ("12 tests passed", "3 files changed", "Build succeeded"), which is the line you would have scrolled back up to find. A one-line result gets no summary card about itself. Each card copies the right thing: the command, the summary, the error *with* its context, and — from the output card — the full log rather than the excerpt on screen. The agent card taxonomy is not reused: "what was wrong", "how it checked" and "asking you" describe prose an agent wrote about its work, and none of it fits a log.
- **Peek opens an overview for any pane.** The three-way "is there an agent here yet" dance that gated it is gone with the reason for it — including the case a slow remote probe could never settle, where peeking a remote pane repeatedly opened nothing. The Command Center board is unchanged and still shows agents only: a shell sitting at a prompt is neither working nor unattended, and you are looking right at it.

- **Fixed: a remote pane that said "Streaming the session from …" forever when the session was simply empty.** The stream was fine. On the machine this was found on the mirror had arrived in full — 32 KB, fifteen lines — and contained zero assistant messages, because that session had not produced one yet. The remote path had only one thing to say about an empty parse, and it was a claim that a transfer was still in progress, so a finished transfer of an empty session was indistinguishable from a hang and stayed on screen indefinitely. Bytes on disk mean the transfer worked, so once any have arrived the pane now says what the local path has always said in the same situation — "No messages in this session yet." — and keeps "Streaming…" for when nothing has come through yet. Both paths that could leave the message stale were corrected, including the unchanged-mtime shortcut, which an idle session makes the only path taken.

- **The overview can split a reply into cards.** A long answer is several different things at once — what was wrong, what it did about it, how it checked, what to watch out for, what it could not do, and the question it is waiting on — and reading it as one column means the question at the bottom looks exactly like the paragraph above it. The card kinds are not invented: they come from the assistant text in every Claude Code transcript on both of this user's machines, about 17,000 messages, and from asking what the sections agents actually write are *called*. The same titles recur on both machines — "what was wrong", "the cause", "what changed", "the fix", "verification", "two caveats", "one thing to flag", "the blocker", "my recommendation" — so those headings are the split, and each card keeps the agent's own title rather than one trm made up. Where an agent wrote no headings, the split falls back to paragraphs classified by content and by position, which the same survey showed is strongly patterned: an ask ends the message 56–60% of the time it appears, "what I did" opens it ~78% of the time, and a caveat sits in the middle ~64% of the time. Asks sort to the bottom and are the only kind drawn in the accent colour, because they are the only kind that is a request rather than a report. Most replies are short and stay a single card — 70–78% of real messages are one block, and shredding those would produce hundreds of cards a day worth reading none of. Cards accumulate as a turn streams: a reply the agent titled itself is split however short it is, so a card that appears does not get rebuilt or re-sorted when the next message lands.
- **trm has an issue tracker of its own**, in the format trm's own checklist window reads — `ISSUES.md` at the root, records under `issues/`, evidence under the gitignored `issues/artifacts/`. It can now be supervised through itself.

- **Fixed: a long reply stopped being spoken partway through.** The worker rendered the whole text in one `generate` call under a `max_tokens=1200` ceiling, and that ceiling caps the *audio* a call may produce — so a long reading hit it and generation simply ended, with no error and no end-of-speech, just silence mid-sentence. It never showed up before because the play button only ever spoke a 620-character briefing, which fits underneath; reading replies in full is what walked into it. The text is split into sentences grouped to a few hundred characters and each group is generated separately, so no single call approaches the ceiling however long the reply is. Those group boundaries are also what skipping back lands on.
- **Playback controls while it speaks: speed, skip, and start again.** A long reply read in full is the case they exist for — at four minutes you need to hear a sentence again, or to get through the rest faster. Speed steps 0.75× to 2× and holds pitch, so faster is faster rather than higher, and it is remembered between replies. Back and forward move ten seconds; skipping back reschedules audio already rendered, since the synthesiser streams forwards once and cannot be asked to produce the same audio twice. Seeks land on a rendered boundary, about half a second. The clock shows a trailing `+` while the reply is still being generated, because until it finishes the end of what you can skip to is not the end of what it said. The controls appear only while something is playing.

- **Speaking a reply reads the reply.** The play button spoke a *summary* — three sentences ranked out of the whole answer — so pressing it to hear what an agent said gave you something it hadn't said. It reads the whole reply now, and the short briefing moved behind ⌥-click, which is the right way round: reading it all is the ordinary want and the digest is the exception. Reading everything does not mean reading it literally. A table is named — "then a table of four rows" — rather than pronounced cell by comma-separated cell, which is what used to happen to a before/after metrics table. A fenced block is named by what it is: a git command, a shell command, a diff, a Swift block. Three blocks in a row become "then three shell commands", one interruption instead of three. Inline backticks are judged span by span rather than stripped wholesale, because `retry` is a word and `git filter-repo --force` is not: a command becomes "a git command", a path becomes the filename a person would actually say, a forty-character SHA becomes "a commit", a URL becomes "a link", and a JSON blob becomes "a value" rather than being spelled out. The parts that are prose are still read in full, in order.
- **Filter buttons for the tags the tracker actually uses.** A row of them under the search field, each with its count, derived from the issues rather than hardcoded: a tracker that never says `@unverified` gets no button for it, and one whose agents are all idle gets no `@working`. Clicking one adds it to the search and clicking it again takes it out, so they compose — `@open` then `@waiting` narrows to both. Agent watermarks are deliberately left out: they come and go with the panes, and a row of buttons that reshuffles itself whenever an agent starts is not a row you can aim at. Those are still one click away on the line itself.

- **Close a pane from its own context menu.** Right-clicking a pane offered Peek, Agent Overview, Switch Remote, Move, Send to Sidebar and Plugins — everything except the obvious one. Closing was reachable only from the pane's *tile in the sidebar*, so the one place you were actually looking at the pane was the one place you could not close it. The item is last and destructive, matching the sidebar's, and a terminal pane still goes through the usual confirmation, so a live agent is not killed by a right-click and a slip. It names what it is closing — an overview, a web pane, a plugin pane, or the whole stack with its count — because "Close Pane" over a stack of four is a worse answer than the number. The underlying action was already correct for every pane kind; it was called `closeSidebarPane`, which is now `closePane`, since the sidebar is no longer the only thing calling it.

- **Mark the issue to work on next, and hand it to an agent.** A button in the inspector, an item in every row's context menu, and ⌘⇧N on the selected issue. Exactly one issue carries the mark — marking a second moves it rather than collecting a list, because "the one to work on next" is a single answer and a window that quietly accumulated five of them would be a queue wearing a different word. The mark is an `@next` tag on the line, so it is visible in place and one click away from being the search. **Hand off now** sends it to a free agent: the issue id, its title, and where the record and the evidence folder are, on one line — a newline in a message sent to an agent's prompt submits it early, and half an instruction is worse than none. It is recorded in `issues/artifacts/<id>/responses.md` before delivery, exactly as a typed response is, so the instruction has a home even if the pane dies between the two. Work is only ever handed to an agent that has genuinely stopped and is on nothing: handing it to one mid-turn interleaves it with what it is already doing, and handing it to one that just asked you a question buries the question. There is a switch to do that automatically the moment an agent frees up — off by default, remembered per project, and it names the agent it would go to, because it is the one control in the window that types into a live terminal without asking twice.
- **The mark is a file, not a preference.** `issues/artifacts/next.md`, one issue id, in the gitignored folder trm already owns and the only place it writes. The tracker's whole premise is that there is no hidden database beside it, and a marker kept in app preferences would have been exactly that: invisible to the agent about to be handed the issue, unreadable by hand, and stranded on one machine. As a file it travels with the project, so marking something on the mini shows up on the laptop. It is read in the same pass as the snapshot rather than separately — a remote tracker polls every five seconds, and a second SSH round trip for one short line would have doubled that cost. Clearing it removes the file rather than leaving an empty one.

- **The project checklist is an outline, not an application.** The old window put a card on the board for every issue and a text editor on every card — sixty-five editors instantiated at once on the tracker this was built against, each asking the model which agents were on its issue, and each of those rescanning every agent transcript against all sixty-five ids. One agent typing a sentence re-derived that whole matrix. The replacement is the shape the tracker already has: `ISSUES.md` is a plain-text file of headings and one line per issue, so the window is that file with the live agent state written into it, in the manner of TaskPaper. A heading is a project line, an issue is a task line, the agent's own sentence is the note under it, and **every other fact is a tag** — `@open`, `@staged`, `@trm-4`, `@waiting`, `@artifacts(3)`, `@next`, `@drift`, `@unindexed`. Deployed issues are struck through, the way `@done` is. Selecting a line expands it in place — the agent's message, what it has been doing, its evidence, the work record, and the one composer — so only the selected issue ever builds a text field or reads an artifact. Gone with the redesign: the navigator, the Focus/List/Board switcher, the board, the cards, the inspector pane and the status bar. What is left is a search field and a document.
- **Everything you can see, you can search for, because they are the same strings.** Clicking any tag searches for it; clicking it again clears the search. The query language is deliberately tiny — `@tag`, `@tag(value)`, `not @tag` or `-@tag`, and bare words matched against the id, title, note and tracker report, all ANDed. That is the whole grammar, because a language you have to learn defeats the point of being able to click a tag to write it.
- **Agent state is still four things, and still honest.** *working*, *waiting for you*, *failed*, *done*, as tags rather than coloured dots. A question outranks everything — it is the only state where the agent has stopped and is blocked on this window — and errors only read as `@failed` once the agent has stopped, because a bad tool call mid-turn is usually one it recovers from. The note line leads with the agent's own sentence, never `Bash cargo test`; the tool calls are still there, under it, when the line is expanded. The agent tag is the pane's own watermark, reduced to something that can follow an `@`, and clicking through to that terminal is one item in the line's context menu.
- **A record with no index row is shown, not swallowed.** The parser already recovered `issues/*.md` files the index had no line for; nothing surfaced them. They carry an `@unindexed` tag now, and `@drift` marks a record whose own `**Status:**` disagrees with the index. On the tracker this was built against those are records whose index line says `FIXED`, `IN PROGRESS` or `DONE (remote)` — none of them words the index's status vocabulary contains, so the row never parsed and only the record survived.
- **Fold a section, or focus one.** Clicking a heading folds it; ⌥-clicking focuses it, which is TaskPaper's own gesture on a project handle, and there is a menu item for people who would rather not know that. Focusing hides every other heading rather than filtering — with seventy-nine issues under seven of them, folding the other six leaves you scrolling past six fold lines to reach the one you want. ⌘9 and ⌘0 collapse and expand everything, the same way round as TaskPaper; with two levels there is nothing for its gradual ⇧⌘9/⇧⌘0 variants to do. A chip in the search bar names what you are focused on and is the way out, since there is no sidebar with a Home row to click. Focusing clears any folds, so leaving it cannot drop you back into a full outline with a section mysteriously shut.
- **`and` and `or` in the search.** `@waiting or @failed` is the one people reach for — everything that wants a human, whichever kind of stuck it is. `and` may be written out between two terms, because TaskPaper writes it that way and refusing it would only be pedantry; it changes nothing. `not` binds to the term it precedes, not to the rest of the query.
- **Keyboard and states.** Arrow keys walk the outline, Return puts the caret in the composer, `/` and ⌘F focus search, Escape pops one level at a time — composer, then search, then focus, then selection — ⌘⏎ sends, ⌘R refreshes. Right-clicking a line opens `issues/<id>.md`, shows it in the index, reveals its artifacts, or jumps to the agent. The first read draws skeleton lines at the real rhythm rather than an empty outline, because "nothing here" and "haven't looked yet" are different answers; an empty search says what was searched; a failed read shows the error verbatim and selectable, and says the thing that matters — nothing was written.

- **Fixed: a remote pane's overview stuck on "Streaming the session from …" with nothing under it.** The transcript had arrived — the mirrors on the machine this was found on were byte-for-byte complete, every line valid JSON, hundreds of messages each — and the panel showed none of it. The 1.5 s poll started a parse without checking whether the previous one had finished, and a mirror parse is not a 1.5 s job: these files run to 15–27 MB, so every tick launched another parse of the same bytes and whichever finished last won. A parse of a mirror as it was moments after `tail -n +1` created it could therefore land *after* a good one and blank the panel. That alone would have healed on the next poll, except for the second fault: the "unchanged mtime, nothing to re-parse" shortcut is the one path that never revisits the status, and a session that has gone idle stops changing its mirror's mtime — so the shortcut became the only path taken and the wrong message was pinned there for good. Nine overviews were re-parsing tens of megabytes every 1.5 s to arrive at the answer already on screen. - **Fixed: with several agent sessions in one folder, the overview could bind whichever was newest instead of the pane's own.** Two causes. Remotely, the SSH probe's folder fallback simply took the newest transcript; it now birth-time-correlates like the local locator — the first transcript created after *that* agent process started (30 s slack) is its session — so two agents sharing a directory each stream their own transcript. - **Fixed: remote sessions landed in a tmp directory zmx defaults to, invisible to trm.** The remote attach command never set `ZMX_DIR`, so remote-pane session sockets went to zmx's default (`$TMPDIR/zmx-<uid>` — periodically cleaned by macOS) instead of trm's `~/.trm/zmx`: the remote machine's Session Browser and `trm sessions` couldn't list them, and the remote Agent Overview's probe couldn't find them ("Session … is not running"). The attach command now pins `ZMX_DIR` to `~/.trm/zmx` on the remote (single-quoted so `$HOME` expands there — usernames needn't match), attaching sessions that already live in the old default dir where they are; the overview probe searches the same fallback chain zmx itself uses. The same missing-`ZMX_DIR` bug in the other direction made `trm attach-remote` (mirror-session.py) and the documented raw `ssh -t host zmx attach` miss *app-created* sessions and silently start empty duplicates in the tmp dir — both now set `ZMX_DIR` too. A dead daemon that left a stale socket now reports as "session not running — reconnect the pane" rather than "no coding agent found". Two subtleties mattered: macOS's `TMPDIR` ends in a trailing slash, and while a `[ -S ]` file test tolerates the resulting double slash, **lsof's name matching does not** — making live daemons look dead to the probe (the trailing slash is now trimmed, as zmx itself does); and the attach fallback requires a *live* daemon (lsof), not just a socket file, so a stale socket can't pin a session to the tmp dir forever — a dead session migrates to `~/.trm/zmx` on reconnect.

- **Bonjour host discovery**: trm advertises itself on the local network as `_trm._tcp`, and browses for other machines running trm, so the remote-pane prompt offers a list of discovered hosts instead of requiring a hostname from memory (typing any destination still works — plenty of hosts aren't on the LAN). What's advertised is deliberately minimal: a name, an SSH port, and — since machines don't share usernames — the account to log in as (`ssh_user` in the TXT record; a bare hostname makes ssh guess with the *connecting* machine's username, which fails between any two Macs with different account names). Discovered destinations are offered as `user@host`; the advertised username is held to the same strict character set as typed destinations before it ever reaches a shell command. trm serves nothing on the advertised port — the transport for a remote pane is plain SSH, authenticated by your existing keys — so this only answers "which machines are around", never "let me in", and Bonjour keeps it LAN-scoped. **Always-on advertising**: trm itself advertises only while the app is open; `scripts/install-bonjour-advertiser.sh` installs a per-user LaunchAgent that registers the service with `dns-sd -R` and keeps it registered via launchd, so a machine stays discoverable with no trm running (`--uninstall` removes it). - **Reload Latest UI**: New menu item **trm → Reload Latest UI** (Cmd+Shift+R) swaps trm into the freshly-installed binary with no perceived lag and without losing your windows. Rather than quitting and relaunching (which leaves the screen empty while the app boots), it does an **overlapped handoff**: the new instance launches *first*, attaches to the same live zmx session daemons, and only once it reports its windows on screen does the old process exit. Because zmx is multi-client — the same mechanism behind `trm mirror` — both UIs briefly render the same PTYs, so there is always something on screen and the underlying shells, agents, and long-running commands never stop. This turns rebuild → `scripts/reinstall-trm.sh` → Cmd+Shift+R into a one-keystroke dev loop, the practical substitute for hot-reloading the UI. The two resources that can't be double-owned are handled explicitly: the successor starts with `[text_tap] enabled = false` (Text Tap's `start()` unlinks any existing socket file, so an eager bind would steal the socket from the still-live predecessor and drop its connected hook clients) and takes the socket over via the new `termania_text_tap_start` C API once the predecessor exits; meanwhile the outgoing process stands down its 30 s checkpoint timer so it can't clobber the handoff state while tearing down. (Opening at the default size and resizing afterwards corrupted the display: a TUI mid-render — an agent's prompt, a pager, an editor — painted at the wrong width and was then reflowed, leaving duplicated and interleaved lines. The frame is applied without animation, and pane-move animation is held down across the swap: `buildCurrentConfigToml` serializes the layout but not the geometry — that normally lives in the autosave manifest, which a `TRM_CONFIG` launch never consults — so without it the reloaded window opened at the default size instead of replacing the one it took over from. ### Performance

- **Live Summary no longer reads full scrollback**: The Live Summary poll (every 8 s when enabled) read the *entire* scrollback of every pane on the main thread, hashed it, and sent it untruncated to the LLM. It now reads only the visible viewport — the same pattern the output scanner already used — eliminating a main-thread stall and the risk of re-introducing the full-scrollback leak.
- **LLM pane context reads viewport only**: `buildPaneContext()` (command palette AI) read each pane's full scrollback even though the system prompt only keeps the last 30 lines. It now reads the visible viewport.
- **Context usage tracking is O(1) per update**: The 1 Hz context-usage poll re-scanned the entire snapshot history on every change and re-encoded the full history JSON on the main thread every ~10 s. Aggregates are now bumped incrementally (full recompute at most every 5 min), history saves are time-throttled (≥60 s apart) and encoded off the main thread, and in-memory snapshots are capped at 50k entries.
- **Claude prompt pill: one process scan per tick, app-wide**: Each window's `ClaudePromptPlugin` enumerated every PID on the system (hundreds of syscalls) every 3 s. The scan result is now cached app-wide with a 2.5 s TTL, so N windows cost one scan instead of N.
- **Text Tap accessor polls throttled**: The C-API status accessors (`termania_text_tap_is_active`, `..._app_name*`, `..._client_count`, `..._active_panes`) each ran a full socket poll (accept + per-client read syscalls) and are called per pane per SwiftUI render pass. Accessor-driven polls are now throttled to at most one per 100 ms; the main event-loop poll is unchanged.
- **Keybinding trace logs downgraded**: Leftover `[newtab-trace]` `log.info` calls on every keybinding action (per-keystroke formatting + log I/O) are now `log.debug`.

### Fixed

- **A remote pane's overview could freeze for a day and never say so.** Some overviews sat on an old turn while the pane beside them carried on working — no error, no "still streaming", just a reading pane quietly describing yesterday. A remote transcript is mirrored by an `ssh … tail -F` writing through an open file handle into `~/Library/Caches/trm/remote-overview`, and the overview reads that mirror back **by path**. Those two stop meaning the same bytes the moment anything unlinks the file: the write still succeeds, into an inode that no longer has a name, while every reader stats a path with nothing behind it. Nothing in the loop could notice — a missing mirror is indistinguishable from an idle one, and the stream is only restarted when its process dies, which this one never does. Found on a laptop after a day: one overview 24 hours stale with 2.5 MB streamed into nowhere, and a second mirror path holding two files at once. **Three ways the file was being taken away, all closed.** The launch-time pruner deleted any mirror older than a day, on the reasoning that nothing is streaming at launch — true of one process, and false the moment a relaunch (⌘⇧R, or a crash and restart) has the new trm running it while the old one still holds its mirrors open; it now skips every path a live mirror owns, because an idle session's mirror stops changing and its age says nothing about whether something is still writing to it. A mirror's `stop()` deleted the file at its path whether or not that file was still *its* file, so a mirror that had already been replaced took its successor's mirror with it; it now checks the inode it created before unlinking. And a stream's termination handler could fire after a restart had installed a new process and handle, closing the live handle and stopping the mirror being written at all — stream callbacks are now tagged with the stream they belong to, which also stops a superseded stream replaying the transcript into the live mirror a second time. **And the mirror now heals whatever else takes it.** Each poll compares the file behind the path with the one the handle is writing to, and restarts the stream when they differ — so emptying the cache folder, or any cause not found here, costs one reconnection rather than an overview that is wrong until the app is quit.

- **The buffer selected itself as it scrolled, under a mouse nobody was pressing.** Text would start highlighting as though a drag were in progress — noticed on a scroll, or after switching away to another app and back — and nothing short of clicking elsewhere made it stop. The selection machinery was working correctly: a terminal knows it is selecting because it was told a button went down, and every pointer movement after that extends the selection until it is told the button came up. The bug was a **press with no release**, and trm had added most of the ways one goes missing. ⌘-clicking a pane peeks it, which *moves* the terminal view into the expanded overlay — the window then has nowhere to deliver the mouseUp, because the view that took the press is no longer there. A click that merely transfers focus to a pane is deliberately swallowed at both ends, and the promise to swallow the release outlived a click whose release never arrived, so it ate the *next* real one instead. And ⌃-click reaches the app as a right-button event, converted back to a left press on the way in: let Control go before the button and the release arrived as a *right* release, leaving the left button held for good. Each of those is fixed where it happens, and the invariant is now enforced rather than hoped for — a release is sent only for a press that was sent, and a button the terminal still thinks is held is cancelled the moment the hardware says nothing is pressed: on the next pointer move, on the next scroll, when the pane loses focus, when its view is moved. Cancelled rather than released, because a synthetic release at an arbitrary moment would open whatever link the pointer happened to be resting on, and move the shell's cursor if it were resting on a prompt.

- **Restored sessions came back pivoted (columns as rows)**: A window saved as a row of panes could restore as a column. `row_cols` is only serialized for jagged/stacked grids, so a uniform grid round-trips through `rows`/`cols` alone — and when the live `gridRowCols` had drifted from the visual pane count, the checkpoint fell back to recomputing the shape from `activeGridConfig`, which is the *launch-time* config and goes stale the moment panes are added, closed, or rearranged. A 3-across window opened from a `rows=3, cols=1` config was therefore written out as `[1,1,1]` — a 3-tall column. The reconciliation now grows or shrinks the layout's *live* shape (widening or trimming the last row) instead of reshaping from unrelated dimensions, so orientation is preserved and a restored window looks exactly like the one that was saved.
- **Agent Overviews lost their group, order, and size on reload**: Four separate breaks in the same seam, each exposed by overviews becoming stackable. The serializer never wrote `stack_group` for an overview (every other pane type did), so a stacked overview came back detached. `restoreStackGroups` counted `agent_overview` entries as *plugins*, which both lost their group and shifted every later pane's index — sweeping unrelated panes into the wrong stacks. Stack restoration ran before overviews existed, so they couldn't join their groups; they now join in a targeted second pass that leaves already-correct groups alone. And because `stackPane` always appends at the bottom, an overview saved *above* its terminal always came back below it — restore now records each overview's saved position and slots it back, transferring host identity when that position is 0.
- **Reordering a stack reset every sub-pane's height**: `moveSubPane` and the drop-to-reorder path both discarded the group's height fractions outright, so any resizing was silently undone by a reorder. Heights now travel with their pane. (`moveSubPane` also cleared the fractions and then tried to read them back one line later to hand to the new host — always nil.)
- **Agent Overview stuck on "Waiting for the pane's working directory"**: With session persistence on (the default), a pane's child process is the `zmx attach` *client* — it has no children and its cwd is wherever trm was launched from, not the project directory. Both of the overview's lookups went through that pid, so the working directory resolved to `$HOME` and the agent process-tree walk (`children[shellPid]`) always came back empty, leaving the overview permanently waiting. The real shell runs under the zmx *server*, reachable via the session socket rather than by walking down from the pane: `ZmxSessionManager.serverShellPid(session:)` asks who holds the socket and takes its first child, and both the cwd and the agent walk now anchor there (falling back to the old path when a session has no live server).
- **Agent Overview drag started but couldn't be dropped**: An overview is pinned to its terminal, so that cell is the *only* valid drop target — and the target test compared against `GridPane.id`, which for a stack reports its *first child's* identity. Whenever the anchor terminal was stacked, nothing would accept the drop and the drag died on release. `validateDrop`, `performDrop`, and `placeOverview` (three separate copies of the same check — the first two agreeing but the third not was why a drop could highlight and still silently fail) now test whether the target cell *contains* the overview's terminal surface, handling plain and stacked cells alike. The overview's **own cell** is now a valid target too: dropping it back onto itself to pick a different side is the natural gesture and previously did nothing.
- **Reload killed panes (and looked like a lost row)**: Reloading could spawn *several* successor processes — four launched within nine seconds in one observed case. Every successor attaches to the same zmx daemons, so each redundant process closed its panes' PTYs as it tore down, sending EOF (`0x04`) to the shells; the daemons logged `shell exited`, tore down their sessions, and the panes closed with `processAlive=false`. This read as the layout dropping its last row, but the panes' *processes* were being killed. Three causes, all fixed: the ready announcement ran from `applicationDidBecomeActive` (which fires on every reactivation, not just launch) and is now made exactly once; the `TRM_RELOAD_PREDECESSOR_PID` marker is cleared once consumed, so a successor is never mistaken for one again; and the reload action now refuses to start while a handoff is already in flight. Reload also validates the *handoff config itself* for dead sessions rather than only the autosave — the two are built separately, so a pane whose daemon had died could pass the autosave check and still be written into the handoff, where `zmx attach` exits instantly and the pane closes.
- **Restoring a session collapsed a row**: A checkpoint containing an agent overview came back with one fewer row — a two-row window flattened into one. Two compounding causes, both fixed. First, agent overviews are created late in restore (they need their terminals to exist), but the seeded `gridRowCols` already counts their cells — so the `reconcileGridRowCols()` that runs right after the terminals are built saw more cells than panes and trimmed the difference, turning a saved `[5,1]` into `[5]` before the overview was ever placed; it now holds cells for overviews still pending. Second, `showAgentOverview` then claimed a cell unconditionally, which is right when opening an overview interactively but double-counts when replaying one from a checkpoint; the claim is now conditional on the grid actually being short a cell, so both callers are correct without either needing to know which case it is.
- **Pane drags broke while pane-move animation was on**: The grab bars are AppKit `NSDraggingSource` views hosted inside the pane cell the grid animates, and an animating layer underneath an in-flight dragging session breaks the drag — which regressed dragging the agent overview by its grab bar. Both drag sources (pane and overview) now hold pane-move animation down for the duration of the drag and release it after the drop's layout change lands, so the pane appears in its new slot rather than sliding into it.
- **Agent Overview ignored the pane-move shortcuts**: Moving an overview with the normal move commands did nothing visible — the generic path reordered the grid, then `repinAgentOverviews()` immediately snapped the overview back beside its terminal. An overview only exists relative to its terminal, so a move now changes its *placement* around that terminal (left/right/above/below) instead of reordering the grid, matching what dragging its grab bar does.
- **Agent Overview took over a neighbouring pane**: Opening an overview displaced an existing pane instead of claiming its own cell. Appending to `agentOverviewPanes` grows `gridPanes` by one, so the `ensurePaneDisplayOrder()` inside `applyOverviewPlacement` saw a count mismatch and rebuilt the display order with the overview already in it — at which point `placeCompanion` treated it as an existing cell, removing it from one row and re-inserting it beside its anchor for a net-zero change to `gridRowCols`. The grid was left with one more pane than cells, so a pane got pushed out. The overview now explicitly claims a cell before placement, keeping cell count and pane count in step.
- **Panes now animate to their new position**: Moving, swapping, reordering, or stacking a pane — and an agent overview claiming its cell — slides the pane into its new slot with a spring animation rather than teleporting. Animation is keyed on each cell's computed geometry and suppressed while a divider is being dragged, so live resizing still tracks the cursor exactly (`PaneDivider` gained an `onDragEnded` callback to signal drag completion).
- **Context usage pill appeared in every window**: The Claude Code context reading is stored process-wide, but each window polled it and rendered the pill unconditionally — so a fresh window with no agent in it showed the context usage of an agent running in a *different* window, and the pill never disappeared once set. Context readings are now attributed to a pane: `context_update` accepts a `"pane"` field (`scripts/claude-context-trm.sh` passes `$TRM_PANE_ID`, falling back to the sender's `mark_connected` pane), exposed via the new `termania_context_pane_id` export, and a window only shows the pill for panes it owns. Readings also expire after 30 minutes, so an agent that goes idle stops leaving a stale number on screen. Readings with no pane attribution (older hook scripts) still show everywhere, as before.
- **Invisible stack sub-pane dividers and typing lag**: Stack sub-pane dividers rendered invisibly, and per-keystroke work in hot paths caused typing lag; both fixed.
- **Phantom selection on pane focus**: Focusing a pane no longer creates a phantom text selection.
- **Pane drag bar**: Dragging by the grab bar now uses an AppKit `NSDraggingSource` (the SwiftUI `.draggable` implementation dropped drags); grip-bar drags are reliable.
- **`GridPane.runShellCommand` uses `/bin/sh`**: was `/bin/zsh -lc`, which sourced user login config and broke on some setups.
- **macOS build on Xcode 26.x + Zig 0.15.2**: replaced `libtool` with a custom `MergeStaticLibsStep` and fixed the xcframework output path resolution.
- **Removed the screen_capture plugin pane** (unused; its registry entries and tests are gone).
- **FFI header drift for `termania_pane_info_s` / `termania_cell_s`**: The C header declarations were out of sync with the Zig structs (`termania_pane_info_s` was missing the leading `pane_id` field; `termania_cell_s` had the color-type byte before the r/g/b triple instead of after). Both APIs are currently unused from Swift, so this was latent — but it's the same class of ABI mismatch that previously caused a release-only crash and a multi-GB leak. The header now matches the Zig layout field-for-field.
- **Text Tap send payloads no longer vanish on truncation**: A send payload longer than 1024 bytes could be cut mid-UTF-8-codepoint, making the whole string undecodable — Swift then silently sent `""` while the client had already received `{"status":"queued"}`. Truncation now lands on a codepoint boundary (also applied to notification title/body), and Swift decodes lossily instead of dropping to empty.
- **Text Tap oversized-message resync**: A JSON line larger than the 4 KB client buffer was silently discarded and its tail bytes were then parsed as a fresh (corrupt) message. The server now replies `{"error": "message too large"}` and discards up to the line's terminating newline so the next message re-aligns cleanly.
- **cmux `id` echoed unescaped**: A request `id` containing quotes/backslashes produced malformed JSON in every cmux response. The id is now JSON-escaped once at extraction.
- **Duplicate URLs in the server-URL banner**: The bare `host:port` pattern re-matched the authority inside already-matched full URLs, so `https://localhost:8443`, `ws://` URLs, or URLs with a path (e.g. `http://127.0.0.1:8080/api`) surfaced a bogus second `http://host:port` entry in the banner. Matches contained inside an already-accepted match are now skipped. (Found by re-enabling the Swift test suite, which had been silently broken — see below.)
- **Stale plugin-registry tests**: Removing the `screen_capture` pane left the registry with 9 builtins, but its tests still asserted 10 (and force-unwrapped index 9, aborting the test binary with signal 6). Tests now match the registry.
- **`zig build test` ran xcodebuild against the old scheme**: The build's `xcodebuild test` step still targeted `-scheme Ghostty`, which no longer exists after the project rename to `trm.xcodeproj` — every full test run failed that step. It now uses the `trm` scheme.
- **`zig build test` hung forever**: The "server broadcast to subscribed clients" test set its check socket non-blocking with `fcntl(F_SETFL, ... | SOCK.NONBLOCK)` — but `SOCK.NONBLOCK` is a socket-type flag, not the `O_NONBLOCK` file-status flag, so the fd stayed blocking and the final `read()` (on a socket that never receives data) hung the entire test run. Now sets the real `O_NONBLOCK` (0x0004), matching what `start()` already does.
- **Text Tap queued-command leak on shutdown**: `TextTapServer.deinit` freed the command list but not the heap-allocated strings of commands still queued between the last drain and teardown.
- **`termania_swap_overlay` double-free window**: The overlay swap re-inserted both panes via `put()`; if the second insert failed, two keys pointed at one pane (double-freed on deinit) while the other leaked. The swap now exchanges the stored values in place.
- **Timer/fd leak when a window controller dies without closing**: `BaseTerminalController.deinit` now invalidates the scrollback-snapshot timer and cancels the config-file watcher; previously these were only torn down in `windowWillClose`.
- **Unbounded memory growth (multi-GB leak) — `ghostty_surface_free_text` ABI mismatch**: The Zig export `ghostty_surface_free_text` took a single `*Text` argument, but the C header and all Swift call sites pass two arguments (`surface, &text`). On arm64 the surface pointer was bound to the text parameter, so the deinit ran against the wrong struct and the actual text buffer was **never freed**. Every `ghostty_surface_read_text` call leaked its buffer — and because the `TerminalOutputScanner` reads each pane's viewport on a repeating poll, this leaked ~1.3 MB/min (~6.7 GB over 4 days). The Zig signature now matches the header (`surface: *Surface, ptr: *Text`), so the buffer is freed correctly. Root-caused with `malloc_history` on a live process (1 ALLOC / 0 FREE on the scanner's allocations).
- **Unbounded memory growth (multi-GB leak)**: The periodic scrollback-snapshot timer (every 30 s, per window) read and re-serialized the *entire* scrollback of every pane on every tick — even when nothing had changed and even while the window sat idle. Each full-scrollback read allocated a large heap buffer (hundreds of KB per pane) that accumulated without bound, growing trm's memory footprint to ~10 GB over multi-day uptime. The snapshot now skips a pane whose visible viewport is unchanged since its last snapshot (a cheap, bounded fingerprint), so idle panes cost nothing and a pane is only re-read when its content actually changes. Explicit session auto-save still forces a full snapshot of every pane. Diagnosed with `malloc_history` on a live release process.
- **`surface.focus` RPC**: The `surface.focus` cmux RPC now correctly focuses the target pane. Three bugs fixed: (1) pane ID lookup in `handleFocusPane` fell back to grid index when `paneId` is nil (matching the same logic as `surface.list`), (2) `focusSurface` now always calls `NSApp.activate` so the trm window comes to front even when another app is focused, (3) `TerminalWindowRestoration` skips macOS native window restoration when `TRM_CONFIG` is set, preventing stale surfaces from a prior session from interfering with a freshly-requested config.
- **`surface.list` duplicate responses**: When multiple windows exist and none is the main window (e.g. trm is in the background), only the first (oldest) controller now responds to cmux queries. Previously both controllers responded, producing duplicate surface entries.
- **Crash opening a new pane (Cmd-T) in release builds**: The Zig `Surface.Options` struct was missing the trailing `reconnect_session_id` field that exists in the `ghostty_surface_config_s` C struct (`include/ghostty.h`) and the Swift `SurfaceConfiguration`. When a split inherited its config via `ghostty_surface_inherited_config`, Swift read that field from uninitialized memory past the end of the Zig struct. In ReleaseFast that memory was garbage (a non-nil bogus pointer), so `String(cString:)` called `strlen` on it and crashed with `EXC_BAD_ACCESS`. Debug builds zero-fill `undefined` memory, so the field read as nil and the bug was invisible there. The field is now declared on the Zig struct so the ABI matches.
