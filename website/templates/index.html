AI Command Palette

Ask AI to run commands, explain errors, or control your terminal. Streaming responses, pane addressing with #0 or #watermark, and a floating status bar that tracks progress when the palette is dismissed.

🧠

Live AI Summaries

Speaking a reply reads the reply. The play button used to speak a three-sentence digest, so pressing it to hear what an agent said gave you something it hadn't said; it reads the whole thing now, with the short briefing behind ⌥-click. Reading everything isn't reading it literally: a table is named (“then a table of four rows”) rather than pronounced cell by cell, a fenced block is named by what it is — a git command, a diff, a Swift block — and inline backticks are judged one at a time, since retry is a word and git filter-repo --force is not. Paths become the filename you'd say out loud, SHAs become “a commit”, URLs become “a link”. While it speaks you get speed (0.75× to 2×, pitch held steady and remembered between replies), ten-second skips either way, and start-again — the controls a four-minute reply actually needs.

Each pane gets a live summary of its terminal output, updated automatically by the LLM. See at a glance what every pane is doing.

GPU Rendering

Ghostty's battle-tested Metal/OpenGL renderer with background images, custom shaders, and 120fps. Zero tearing, efficient redraw.

Quick Terminal

A terminal that drops from the top of the screen on ⌃` and goes away again when you’re done. The binding is global, because a drop-down terminal you can only summon from the terminal is a window you already had — the point is the thought that arrives while you’re in a browser or an editor. Control-backquote rather than the ⌘` the docs reach for first: macOS spends that one on “next window in this app” in every application, and taking it system-wide is a large thing for a default to do quietly. Rebind or remove it like any other keybind.

⚡

Multi-Pane Grid

Jagged grid layout where each row can have different column counts. Drag dividers to resize panes. Option+drag an outer edge to create a new row or column. Hover a pane's top edge to reveal its grip bar, then tap it to expand the pane for a closer look — or drag it to move and stack panes — drop on the top or bottom half of a pane to choose where it lands, or drop it into another trm window to move it there. Cmd+click any pane to peek it the same way. Broadcast input, navigate with keyboard, jump with Cmd+1-9. Cmd+D opens the Quick Terminal rooted in the focused pane's folder.

🪄

LLM-Built Extensions

Describe an extension in plain language and trm's LLM builds it: "notify me when any pane prints BUILD FAILED." Simple automations become declarative if-this-then-that rules (no code, can't leak); complex ones become supervised out-of-process programs with enforced capabilities, memory caps, and crash-restart — in any language. Hot-reloads on edit.

Detachable Sessions

tmux-style persistence without tmux — now on by default. Every pane runs under its own session daemon — quit or even kill -9 trm and your shells keep running; relaunch and it reattaches instantly, no questions asked. And an AI agent survives a reboot — the one event a session daemon cannot outlive. Every daemon dies with the machine, so panes come back as fresh shells; but Claude Code and Codex keep their conversation on disk, so trm records which conversation each pane was having and restarts the agent on it with --resume. A lighter restore than a relaunch: not the process back, but the thirty turns back. Typed into the shell rather than made the pane’s command, so a resume that fails leaves you at a prompt instead of a dead pane. Remote panes too — the case that needs it most, since the machine doing the work is usually the one being restarted. Their agent lives on the other machine, so that machine is asked directly at restore, once per host rather than once per pane, and one round trip answers the whole question: which sessions are gone, and what each was talking about. A session still running is left strictly alone — its agent is still sitting in it, and typing would arrive as a prompt rather than a command. Layouts checkpoint every 30 seconds — and a restored window comes back the size and place it was saved at rather than the built-in default that squeezes a 2×2 grid into four unusable cells, with a frame saved on a monitor you have since unplugged pulled back onto a screen that exists; a brand-new window with no session behind it opens at the last size you worked at. Pane titles survive the round trip now too, and a checkpoint that happens to find no windows open — the timer ticking between windows, or the last one closed a moment before you quit — leaves the last good snapshot alone instead of erasing it. Attach from any terminal with trm attach, open a second UI on the same window with trm mirror — mirrors now follow the primary's layout live: rearrange, stack, or resize panes and every attached UI updates within a second — or show a remote machine's window locally with trm attach-remote — GPU-rendered here, processes there. Single panes can go remote too: remote panes run their shell on another machine over SSH, with the session daemon living on that host so the work keeps going without you — and trm finds other trm machines on your network over Bonjour, so you pick one from a list instead of typing a hostname. Started locally and changed your mind? Right-click a pane → Switch Pane to Remote (or trm.switch_remote) re-points it at another Mac in place — the local session detaches and keeps running (find it again in the Session Browser), while the same cell reconnects over SSH with the work now living on the other machine. A fresh pane switches with no dialog; one that's mid-task warns you first. Remote panes are first-class: even the Agent Overview works on them — trm finds the agent running on the other machine over SSH and streams its transcript live, so you can read a remote Claude's work the same way you read a local one's. Prompts stay readable, too: big pastes collapse to a [Pasted text +N lines] badge just like the CLI, fenced code in your prompt renders as real code blocks, and pasted images show up inline as thumbnails. And when the link drops — sleep, Wi-Fi, moving networks — the pane stays put, holding its last frame, and shows a Reconnect button that reattaches the same remote session in one click — in the peek as well as in the grid, since peeking a pane is what you do when it looks wrong, and reconnecting from inside a peek keeps you on the pane you were reading: the work on the other machine never stopped. After your Mac wakes it doesn't even wait to be asked — every remote pane reattaches itself, because opening the lid isn't a decision about any one pane. trm can tell a dropped link from a deliberate exit because it asks the other machine which one happened — the session is either still there or it isn't — so quitting a remote shell closes the pane exactly like a local one, and only a real disconnect holds it open. And File → New Remote Pane (Cmd+Shift+N) opens a pane on another machine in one keystroke — when a single other trm Mac is advertising on Bonjour it's used automatically, no questions asked — the machine you're on is never mistaken for a remote target, whatever name its Bonjour record uses; otherwise the prompt comes prefilled with the last address you connected to, so the second pane to the same machine is just Enter. Reconnects are faithful, too: reattaching used to hard-break every soft-wrapped line, so copying a long URL an agent printed pasted with newlines in the middle — now the replay preserves wrapping, and copy after a reconnect behaves exactly like copy before it. Want a machine discoverable even when trm isn't running on it? A one-line installer (scripts/install-bonjour-advertiser.sh) keeps it advertising via launchd. Upgrading trm? Reload Latest UI (Cmd+Shift+R) hands off to the new build with no perceived lag — the new UI comes up attached to the same running processes before the old one exits, so your windows never leave the screen. The closest thing to hot-reloading a terminal.

trm on your iPhone

An agent that asked you something at 11pm is blocked until someone answers — and the answer is usually a sentence. View → Pair iPhone… shows a QR code; scan it once and your phone has the same Command Center board: which agent is working, which is stuck, what each one just said, and a box to reply into any of them. Your reply arrives as keystrokes in that pane, exactly as if you had typed it at the desk. It speaks its own small protocol rather than exposing trm's full control socket — the phone can read the board and type into the panes it lists, and nothing else — over a token you can rotate to revoke every paired phone, found on the network by Bonjour or reached by Tailscale address when you're nowhere near the Wi-Fi. Tap a row’s watermark to read the terminal behind it — the session’s own scrollback, over the same connection, for when the summary is the thing you doubt. Pair each machine you run agents on: the phone keeps a pairing per Mac and dials each one directly over its tailnet address, so the mini’s agents stay readable and answerable with the laptop shut — and a machine publishes the sessions it hosts, not just the panes it shows, so an agent running on a Mac with no window open for it still reaches your pocket. And when it can’t connect, it says which address and port it dialled — a bare “connection refused” is equally consistent with the Mac being asleep and with the phone holding a port from a pairing two restarts ago.

Command Center

Worktrees get their own pane. A worktree is a branch you can be in two places at once — one pane on main, another on what an agent is building. Worktree panes wear a ⑂ so you can tell two panes on one project apart at a glance. New Worktree… asks for a branch name and does the rest: creates it beside the repo, opens a pane there, parks it on the sidebar and slides the shelf open. And trm watches the repos its panes are in, so a worktree an agent created gets a pane too — which is the case that matters, since an agent has no way to tell trm what it just made.

One panel, every agent. View → Command Center (Cmd+Shift+A) opens a panel down the edge of the window — a view of your panes rather than one of them, so it costs no grid cell — and it gathers the message each running agent is on right now — the same paragraph its Overview would show — for every pane in every window, labelled with the pane's own watermark, its project directory, and the machine it runs on when it's remote. A dot says which state each one is in: orange when it asked you something and is blocked, green while it's working, grey when idle — and the list sorts in that order, so whatever needs you is at the top. Click a row to open its reply box, double-click its header to go to that pane, ⌘-click to open its full Overview, or type a reply straight into the row — ⌘-click that box (or the expand button beside it) and that row takes the whole panel, divided into two equal halves — the other agents step aside, and what the agent said gets exactly as much room as what you are writing back: above, the state it is in, what you last asked in full, what it actually did this turn, the reply itself and its links; below, an editor where Return breaks the line instead of sending; nothing leaves until ⌘↵, and Escape puts the board back with your draft intact — for the answers that are a paragraph rather than a sentence — with Up-arrow history spanning what you sent from trm and what you typed at the agent, and drag or paste a screenshot, log or diff onto the box to hand it over (copied to the remote machine first, so an agent on another Mac can actually open it) and it lands in that agent's input, wherever the pane happens to be. Drag the panel wide and the rows become a grid of identical cards — at half the window or more it stops being a strip beside your work and becomes a wall of everything that's running. And switch on briefing mode and the wall becomes a launch console: one larger line per agent summarising what it just did, colour-coded needs you / check this / working / idle, with a second line only when something actually wants a decision — and an idle row fidgets: a little ASCII dog that has brought the frisbee back and keeps nudging it your way, because “finished, waiting on you” is the one state a colour can’t say — what it's waiting on, or the error it kept hitting. Read the board, tap the one that needs you, and you're in the pane — including when a pane is peeked, where the peek is put away so you land on the pane itself rather than leaving it hidden behind the one you were reading. Right-click a row and Exit Pane closes that pane for good — the board is where you find out an agent has finished or wedged, so it is where you can end it, with the same confirmation the grid’s own close goes through; the row goes when the pane does. Double-click a row’s watermark to rename that pane from the board: Return renames it, Escape leaves it alone, a blank name clears the watermark, and clicking away commits rather than discards — noticing a pane is misnamed and fixing it become the same gesture. The Overview gained a compose box too: read what the agent said and answer it without going to find its terminal. And agents can now tell trm which transcript is theirs — one command installs Claude Code and Codex SessionStart hooks, here and on the machines your remote panes run on, so binding a pane to its conversation stops being an inference from file timestamps and starts being a fact.

Issue Outline

A window for supervising agents against a real issue list. Any project that keeps an ISSUES.md beside an issues/ folder gets a checklist button on its pane chrome. The window it opens is one column and a search field, because the tracker is already a plain-text outline and the useful thing is to show it as one, with the live agent state written in. There is no database and nothing is ever rewritten: the index stays the source of truth, and the only thing trm writes is your reply, appended to issues/artifacts/<id>/responses.md before it is handed to the agent, so the instruction has a durable record even if the pane exits between the two.

It looks like the file it reads. A heading is a project line, an issue is a task line, the agent's own sentence is the note under it — and every other fact is a tag: @open, @staged, @trm-4, @waiting, @artifacts(3), @next, @drift, @unindexed. Deployed issues are struck through the way @done is. Click any tag to search for it, click it again to clear — what you can see and what you can filter by are the same strings. The query language stops at five things: @tag, @tag(value), not @tag, bare words, and or between alternatives — @waiting or @failed being everything that wants a human, whichever kind of stuck it is. Click a heading to fold it, ⌥-click to focus on it and hide the rest, ⌘9 and ⌘0 to fold and unfold everything. A row of filter buttons under the search field carries whichever tags the tracker actually uses, with counts, and they compose — @open then @waiting narrows to both. Selecting a line expands it in place — the agent's message, its recent tool calls, its evidence, the work record, and one composer — so only the selected issue ever builds a text field or reads an artifact. There is no navigator, no view switcher and no inspector, because the document is the interface.

Mark the one to work on next. An item in the line's context menu, ⌘⇧N on the selected issue — exactly one issue carries the mark, and it shows up as @next on its line. Hand off now sends it to an agent that has genuinely stopped and is on nothing: the id, the title, and where the record and evidence folder are, recorded in issues/artifacts/<id>/responses.md before it is delivered. A switch does that automatically the moment an agent frees up — off by default, since it is the one control here that types into a live terminal without asking twice. The mark itself is a file, issues/artifacts/next.md, so it is readable by the agent about to be handed the issue, editable by hand, and travels with the project rather than being stranded in one Mac's preferences.

Session Browser

Now spanning machines: the browser also asks your other Macs what they are running — anything on Bonjour, every host a saved window has put a pane on (so Tailscale and VPN addresses count too), and the last one you connected to — and lists each machine's sessions as its own group, with the same command, directory and attached state as a local one. Open attaches over SSH and resumes the process; terminate kills it on the far side. Work you started in a remote pane is no longer invisible from the machine you are sitting at. Because sessions outlive the UI, work can keep running with no window showing it — after a hang, a crash, or a layout that got lost. View → Session Browser (Cmd+Shift+S) shows live sessions grouped by the window they belong to and laid out in a grid that mirrors the real window, each tile carrying that pane's watermark — the same label the pane draws on itself — so you recognise a session the way you already recognise it on screen. Restore a whole window in one click, or open a single pane — either way it reattaches to the existing process, it doesn't start a new shell. Sessions no saved window refers to are collected under Ungrouped, which is exactly where lost panes turn up. Previews are read-only snapshots, so browsing never steals a session from the window that owns it — and opening a session that is already on screen simply brings that window forward. Restoring a window brings its panes back attached to the processes that were already running in them.

Pane Sidebar

Close a pane from its own right-click menu. It was reachable from the pane's tile in the sidebar but not from the cell you were looking at. Destructive and last in the menu, with the usual confirmation on a live terminal, and it names what it is closing — an overview, a web or plugin pane, or the whole stack with its count.

Not every pane needs to be on screen all the time. View → Send Pane to Sidebar (Cmd+Ctrl+H), or the pane's context menu, moves a pane onto a shelf at the right edge and lets the rest of the grid expand into the space it left — but the pane keeps running: same shell, same session daemon, same agent mid-task. This is deliberately not a close, which would kill the pane's session; parking only stops drawing it, so the long build, the log tail, and the agent you'll read later all carry on out of sight. View → Show Sidebar (Cmd+Ctrl+S) opens the shelf, which lists parked panes as small watermark cards about the size of a Session Browser tile — click one to bring it back where you left off, or Restore All for the lot. A parked agent that starts waiting on you lights up orange on its card, so nothing important goes quietly missing. Collapsed, the shelf becomes a narrow rail with a count rather than disappearing — a running pane always has a visible way back — and it drags to whatever width you want. An Agent Overview parks and returns alongside the terminal it describes, and a stack parks as a group. Parked panes survive quit and relaunch, and show up parked in trm mirror windows too.

Agent Overview Pane

Cards lay out as a grid. One column in a narrow pane, two or three when you peek it — the same view is 300 points wide in the grid and three times that expanded, and a single column across a wide peek wasted most of it. Cards are dealt across the columns in order, so left-to-right still reads them in the order they were written, and each column is its own stack so a three-line command card beside a forty-line output card doesn’t leave a hole the size of the taller one.

It works on panes with no agent in them. A shell has the same shape as a conversation — you type something, it answers — so the overview reads the pane’s scrollback back into that shape: every command is a turn, its output is the reply, and the ‘ ’ arrows page back through them exactly as they page through an agent’s. It finds the prompt by what it looks like, including themes that print the directory and git branch after the marker, and a pane sitting inside one long-running program (a dev server, a tail -f) is read as that one thing rather than as nothing. Failed lines are picked out of the output — a compiler error, a traceback, command not found, a CLI complaining about a flag — while the lines that mean success (“0 errors”, a warning, “Build succeeded”) are left alone. Three copy buttons sit at the top: the full log, the command with its output, and the error with the lines around it, which is the one you actually want to paste, since an error line alone rarely says which file it came from. In card mode a command becomes cards: what ran and what kind of work it is (build, tests, version control, packages, containers…), how it went, what failed, and the output — each with its own copy button.

Split a reply into cards. A long answer is several things at once — what was wrong, what it did, how it checked, what to watch out for, what it couldn't do, and the question it's waiting on — and as one column the question at the bottom looks like every paragraph above it. The kinds aren't invented: they come from reading the assistant text in every Claude Code transcript on both machines, ~17,000 messages, and asking what the sections agents actually write are called. The same titles recur — “what was wrong”, “the fix”, “verification”, “two caveats”, “the blocker” — so those headings do the splitting and each card keeps the agent's own title. Asks sort to the bottom and are the only kind in the accent colour, because they're the only kind that's a request rather than a report. Short replies stay one card, and cards accumulate as a turn streams rather than rearranging when the next message lands.

A native reading pane for your agent — works with Claude Code and Codex, and binds to the agent running in that pane even when several share a folder. A dropdown picks what it shows: everything, just what you asked, just the commands it’s running, just the reply, or only the errors — the handful of failed tool calls buried among hundreds. It behaves like any other pane: stack it, swap it, move it by shortcut, put it anywhere in the grid. Replies lay out as real Markdown — headings, lists, tables, quotes, task items, inline code — instead of exposing the markers as text, and when Claude asks a structured question the overview shows the full card: the question, every labeled choice, and the answer once it’s given. A font menu switches the whole reading surface between system and monospace type, per pane, and a speaker button reads the reply aloud with the best neural voice installed on your Mac — fully local, code blocks politely skipped. The sentence being read is marked on the page as it is spoken, so a reading you are half-following has a place to look rather than being a voice you have lost your position in — found by looking the sentence up in what is on screen, since the reading is a rewrite of the reply and no offset maps one onto the other. Stopping is a pause: the audio already made and your position in it are kept, so play carries on instead of restarting a four-minute reply from the top, and you are picked up on a sentence boundary rather than mid-word. The skip buttons move seven seconds — a sentence — rather than a music player’s ten. The reader also takes a tone: an unanswered question sounds like someone waiting on you, good news sounds quietly pleased, and the same failure three times over sounds worn down — frustration is earned by repetition, matched on the shape of an error rather than its exact text, because “3 tests failed in 4.12s” and “3 tests failed in 3.80s” are one wall hit twice. The moods are few and slight, and the voice description never changes underneath them, so the feeling moves and the speaker does not. A reading outlives the panel it started from: press Escape on a peek and the voice keeps going, with the scrubber, skip, speed and stop moving to a bar at the top of the Command Center — dismissing a view is not a request for silence, and the board is the one panel that is about every pane rather than any one of them. Open that pane’s overview again and it picks the reading back up where it is rather than offering to start a second one. ⌘-click anywhere in it to expand it for a proper read — and the peek expands the pair: drag either edge of a peek to size it, double-click to snap back to default — The sidebar filters as you type — across a pane’s name, its agent, its directory and the last thing that agent said, which is usually the part you actually remember. And peek the terminal and the overview comes along — opening itself if it wasn’t already, and closing again when the peek does, so a glance never spends a grid cell — peek the overview and the terminal appears beside it, focused and ready to type at. The readable half and the raw half, reviewed together. It carries its terminal’s watermark so you can always tell whose it is, and survives session save/restore. Flip on bionic reading to skim faster. Headings copy their whole section on tap and a code block copies on a click anywhere in it — code is a thing you take whole, so the whole block is the button, lit under the pointer so you can see it is one — and URLs the agent prints are live too — the cursor becomes a pointing hand right over them — tap one to copy it, or hold ⌘ while hovering to preview the page in place: no browser detour, no fiddly text selection in a narrow column. And it isn’t stuck in the present: ‹ › arrows — or the left and right arrow keys, while you’re pointing at it — page back through earlier turns — what you asked, what it did, what it said — with one tap back to the latest.

Crash-Safe Plugin Isolation

Plugins run as subprocesses. If one crashes, trm keeps running. No reload, no restart, no lost work.

🛡

Isolated Processes

Each subprocess plugin runs in its own process with stdin/stdout JSON pipes. A crash is just a pipe EOF — the host detects it instantly.

🔄

Auto-Restart

Crashed plugins restart with exponential backoff (2s, 4s, 8s). After 60 seconds of stable running, the retry counter resets. Three strikes and the plugin stays down — your terminal stays up.

🌍

Any Language

Subprocess plugins are standalone executables. Write them in Python, Rust, Go, or anything else. Read JSON from stdin, write state to stdout. That's the whole API.

Quick Start

1

Download

Grab the latest release from GitHub:

Download for macOS

Or build from source:

git clone https://github.com/keyvez/trm.git
cd trm
zig build -Doptimize=ReleaseFast
2

Create a config

# ~/.config/trm/trm.toml
title = "My Project"
rows = 2
cols = 2

[[panes]]
title = "Editor"
cwd = "~/projects/myapp"
watermark = "EDIT"

[[panes]]
title = "Server"
initial_commands = ["npm run dev"]

[[panes]]
title = "Tests"
initial_commands = ["zig build test"]

[[panes]]
type = "webview"
title = "Docs"
url = "http://localhost:3000"
3

Launch

# From your project directory
trm

# Or specify a config file
